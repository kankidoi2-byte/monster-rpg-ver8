# 開発司令塔 基盤

Phase 12の独立したNode.js実行基盤です。ゲーム本体から読み込まず、GitHub Pagesにも組み込みません。

## 現在の境界

- 初期状態は `127.0.0.1` だけで待ち受けます。
- 認証なしで公開するのは `GET /healthz` だけです。
- GitHub API、セーブ、外部送信、書き込み操作には接続しません。
- GitHubトークンやAPIキーはまだ使用せず、リポジトリへ保存しません。
- 0.0.0.0などへ変更する場合は、非公開ネットワークが別途確保されていることを環境変数で明示する必要があります。

## ローカル確認

1. 必要なら `.env.example` を参照して環境変数を設定します。`.env` 自体はGit管理対象外です。
2. `npm --prefix tools/dev-command-center run check` を実行します。
3. `npm --prefix tools/dev-command-center start` を実行します。
4. `http://127.0.0.1:4174/healthz` を開きます。

実際の非公開ホスティング、アクセス制御、秘密情報の設定はPhase 12の対象外です。

## Phase 13: GitHub読み取り

`src/github-reader.mjs` は固定GitHub REST APIへGETだけを送り、コミット、ブランチ、オープンPR、オープンIssueを制限付きで取得します。Issue/PR本文とコメントは保持しません。

公開リポジトリはトークンなしでも取得できます。トークンを使う場合は `DEV_COMMAND_CENTER_GITHUB_TOKEN` を秘密管理機構から実行環境へ渡し、ファイル、URL、ログには保存しません。Phase 13では実トークン設定や外部ホスティングを行いません。

## Phase 14: GitHub Actions読み取り

`src/github-actions-reader.mjs` は直近20件のworkflow runと、最新runの最大100 jobをGETだけで取得します。workflow、対象SHA、状態、開始・終了時刻、失敗job、GitHub上の確認URLを固定形式へ正規化します。

ログ本文は秘密情報が混入する可能性があるためダウンロードしません。`log_url` はGitHub上で人間が確認するためのHTTPS URLだけです。workflowの再実行、キャンセル、dispatchなどの書き込み操作も実装しません。

## Phase 15: GitHub Pages読み取り

`src/github-pages-reader.mjs` はPagesサイト情報と最新ビルドをGETだけで取得し、公開状態、公開URL、公開元、対象SHA、公開時刻を固定形式へ正規化します。

公開URLのqueryとfragment、pusher情報、エラー本文、CNAME、証明書情報、レスポンス生データは保持しません。Pages設定変更、ビルド要求、デプロイ作成・取消などの書き込み操作も実装しません。

## Phase 16: 統一ステータス

`src/unified-status.mjs` はPhase 13〜15の読み取り結果を、正常、作業中、確認待ち、失敗、公開待ち、情報が古い、取得不能の7状態へ決定的に統合します。

判定は固定された優先順位とreason codeだけを使い、AIや自由文の解釈、追加の通信、GitHubやPagesへの書き込みは行いません。mainのコミット、CI対象SHA、Pages公開対象SHAを照合し、古い情報や部分的な取得不能を正常扱いしません。

## Phase 17: 次の作業判定

`src/next-action.mjs` はPhase 16の7状態だけを入力にし、優先度、操作code、理由code、確認リンク、作業を止めている状態を固定形式で返します。数値の小さい優先度ほど先に扱い、失敗、取得不能、古い情報、CI実行中、公開待ち、確認待ち、正常の順に一意に決定します。

AIや自由文を判定に使わず、不明な入力は取得不能として復旧操作を選びます。確認リンクはHTTPSのGitHubまたはGitHub Pagesだけを許可し、認証情報、query、fragmentを除去します。通信、GitHub操作、承認、ゲーム本体への組み込みは行いません。

## Phase 18: スマホ用ダッシュボード

`http://127.0.0.1:4174/` はPhase 13〜17の読み取り結果を、総合状態、次作業、main、PR数、CI、Pages、更新時刻の一画面へまとめます。画面幅360 CSS pxから利用でき、ページ再読込による明示更新、キーボード操作、見えるフォーカス、44px以上の操作領域に対応します。

認証機能がまだないため、ダッシュボードはループバックで起動した場合だけ表示します。外部スクリプト、ブラウザ保存、書き込み操作はなく、GitHub情報はサーバー側の既存読み取り専用アダプターから取得します。

## Phase 19: 診断レポート取込コア

`src/diagnostic-import.mjs` は、ゲームが生成した版付き診断JSONを手動入力として受け取り、入力サイズ、深さ、要素数、対応版、必須セクション、件数の整合性を決定的に検証します。

受理後に返すのは、生成時刻、アプリ版、関連コミット、画面・端末区分、固定形式の件数と利用可否だけです。入力JSON、セーブ内容、個体UID、エラー本文、URL、未知の項目は保持しません。秘密情報らしいキーや値、query・fragmentを含むURLはレポート全体を拒否します。

取込はループバック専用ダッシュボードの明示操作からだけ実行し、正規化結果は現在のサーバープロセス内のセッションに限定します。ファイル保存、ブラウザ保存、外部送信、GitHub書き込み、ゲームセーブ変更は行いません。

## Phase 20: GitHub Issue下書き生成

`src/issue-draft.mjs` は、ダッシュボードの固定状態とPhase 19で受理済みの安全な診断要約だけから、題名、根拠、再現条件、影響、重複候補、ラベル候補、確認リンクを決定的に生成します。正常または処理中の状態では、不要なIssueを増やさないよう下書きなしを返します。

生成結果はループバック専用ダッシュボードで「未投稿」と明示し、現在のサーバープロセス内だけで表示・消去します。GitHub APIへのPOST、認証権限の追加、外部送信、ファイル・ブラウザ保存は行いません。重複Issueの照合と実際の投稿はPhase 21の明示承認付き操作まで実装しません。

## Phase 21チェックポイント: 投稿承認コア

`src/issue-publication-approval.mjs` はPhase 20の固定下書きとPhase 13のオープンIssue一覧を照合し、同名Issueがあれば投稿準備を停止します。重複がない場合だけ、下書きのSHA-256指紋、完全一致の確認文、5分の有効期限、1回限り、必要権限 `issues:write`、外部影響と取消方法を固定形式で提示します。

このチェックポイントは承認の準備と検証だけを行う純粋処理です。GitHub API、トークン、環境変数、投稿エンドポイント、永続保存には接続しません。Issue書き込みアダプターと権限設定は、外部投稿の影響に対する明示承認を得るまで追加しません。

## Phase 21: 毎回確認付きIssue投稿

`src/github-issue-writer.mjs` は、Phase 21承認コアが発行した有効な1回限りの認可だけを受け付け、固定リポジトリのIssue作成APIへ題名と本文だけをPOSTします。投稿準備では最新のオープンIssueを再取得して同名重複を停止し、画面に投稿先、必要権限、下書き、有効期限、完全一致の確認文を表示します。

各投稿には「この下書きをGitHub Issueとして投稿する」の再入力が必要です。確認は5分で失効し、下書き変更、取消、二重送信、認証・権限・GitHub障害ではfail closedになります。失敗後の再試行にも、新しい重複確認と確認文入力が必要です。自動投稿、バックグラウンド投稿、ラベル・担当者・マイルストーン設定は行いません。

書き込み用トークンは読み取り用と分け、`DEV_COMMAND_CENTER_GITHUB_ISSUE_TOKEN` からサーバープロセスだけが読み取ります。対象リポジトリだけのfine-grained tokenとし、Repository permissionsは `Issues: Read and write`、その他はGitHubが必須とするMetadataの読み取り以外を付与しません。値を `.env.example`、リポジトリ、URL、ブラウザ、ログへ保存しないでください。トークン未設定時は確認後も投稿せず固定エラーで停止します。

## Phase 22: 総合検査

`test/comprehensive.test.mjs` は、認証切れ、レート制限とAPI部分失敗、古い状態、360pxスマホレイアウト、秘密情報の非開示、読み取りAPIのGET限定、Issue投稿の別トークン・完全一致・5分・1回限りの境界を横断検査します。

検査は固定fixtureとローカルサーバーだけを使い、実GitHub APIへのIssue投稿、トークン設定、ゲーム本体・セーブ変更を行いません。Phase 22自体はテストと検証記録のみのため、プレイヤー向けお知らせと新しい実機確認は不要です。
