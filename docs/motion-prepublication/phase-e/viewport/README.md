# 戦闘画面の高さ調整

2026-10-01。本人の「バトル画面が1画面に入りきっていない」指摘を受け、縦配置の調整を実装。採用済みの各モンスターのlayout.scale、sourceBounds、反転、メディア・画像・ゲームデータ・セーブ・戦闘ルールは変更していない。

旧レイアウトは敵/味方の画像を別々の大きい行に置き、能力と表示設定もHPの下に積み重ねていた。新レイアウトでは敵を右、味方を左の同じ画像行に置き、敵HPを上、味方HPを下に分離する。3体時の敵2体は右側の2トラックを使用。

実際の上部バー・マップ・HUD・操作部の高さを測定し、残りの高さから画像行を決める。全員に共通のサイズ単位を適用し、採用した体格比率を維持する。文字200%や開いた情報、対象選択、戦闘結果などが大きい場合はスクロールを許可し、画面を切らない。48pxの主要操作領域を保持。フレーム毎の計測/新動画の割当ては行わず、共通ResizeObserverと1回に集約したrequestAnimationFrameを使用。

能力・表示設定は画面下の折りたたみへ既存ノードを移動し、ID・イベント・再試行ボタンと動画の寿命を保持。戦闘履歴と同じ行に置く。確認ページのモンスター/背景設定も折りたたみにし、外側の説明の高さに合わせてiframeを伸縮させる。

検証：全体npm run checkはpostcheck込みPASS。戦闘/モーション関連8検査PASS。追加検査は30,000通りの味方/敵2体/画面寸法で包含と共通単位を確認し、実測を模したDOMで予算適用と短い画面でのスクロールfallback、情報の保持・切替を確認。旧戦闘DOM検査の履歴末尾条件を新ツール行へ更新し、既存media APIの未実装をmockで扱った。検査は実ブラウザのCSSピクセル配置や実動画の再生を証明しない。

本人限定Siteへ反映する。通常操作は /game/index.html?case=journey、戦闘へ直接入る確認は /game/index.html。以前の通常戦闘案内URLは直接戦闘fixtureに入るため、通常経路の確認にはjourneyを指定する。種類・マップ確認は /game/tools/motion-review/gran-volmoog-review.generated.html。

残り：Galaxyの通常文字・縦画面でHPとコマンドまで見えるか、横向き・文字200%で操作が隠れないか、動画・交代・乱入・画面復帰の確認。前回のサイズ採用は保持するが、配置変更後の新しい実機受入とは区別。本編mainへのマージ・一般公開は引き続き禁止。
