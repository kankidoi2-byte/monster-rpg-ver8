# 動画の読み込み・解放点検

対象：公開済みの50体登録と再生管理。実ブラウザのNetwork/メモリ計測ではなく、ソース監査とDOM/media mock検査。

| 経路 | 点検結果 |
| --- | --- |
| 起動・非戦闘画面 | 動画レコードを作らない。50本をまとめてpreloadしない |
| 初期画面外・控えめ設定 | 停止理由を判定してからsrcを割り当てる。初期停止中は動画取得を始めない |
| 再生枠 | 通常1体、明示設定の上限3体。静止素材のサイズと再生枠を分離 |
| HP・技・アイテム画面 | 同じ動画を保持し、不要な再取得や時間リセットを抑制 |
| 背景化・一時的な画面外 | pauseして復帰時に再利用。既に取得を始めた動画の取得キャンセルを保証する設計ではない |
| 戦闘終了・交代・離脱・pagehide | タイマー/observerを解除、pause→src解除→load→要素削除。古いイベント・Promiseを無効化 |
| 読み込み失敗・5秒の前景待ち時間超過 | 修正前はpauseのみで取得元が残る。修正後はsrc/ハンドラ解除とloadで取得/復号資源を解放。静止素材と再試行の操作を維持 |
| 手動再試行 | 1表示につき1回。空の旧要素を外し新要素を生成。連打や古い失敗通知が新試行に干渉しない |

通常の一時停止では復帰用に動画を保持する。停止と完全解放を混同して、画面を切り替えるたび全動画を取り直す変更は加えない。今回の修正は失敗時の不要な取得を止める範囲に限定する。

ライフサイクル検査で、再試行を押す前の失敗時点でsrcとハンドラが解除されること、1敵の失敗/再試行が他の動画へ影響しないことを追加確認。全体・単体・複数・画面外検査を使用。実メモリ/温度/デコーダ解放の時間は端末依存で、mockによって数値合格としない。
