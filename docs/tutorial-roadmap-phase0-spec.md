## 3. フェーズ1の固定仕様：三つ巴バトル画面

### 画面構成

`battle`画面を共通の戦闘画面として使い続ける。通常戦の単体敵カードは残し、三つ巴／乱入時は敵Aと敵Bを**横に2枚並べるコンパクトカード**へ切り替える。スマートフォン縦画面でも、2体のHP・状態異常・ステータス変化と対象選択を同時に比較できることを優先する。

1. マップ・難易度・三つ巴／乱入の短い識別
2. 味方モンスター
3. 横並びの敵A／敵Bカード
4. 折りたたみ可能な戦闘ログ
5. 画面下固定の技・契約・道具・逃走

各敵カードは、画像、名前、HP、状態異常、ステータス変化、撃破状態を常時読めるようにする。レベル、属性、素早さなどの補助情報は、通常時にカードをタップして開く詳細へ収める。技を押した後はカードタップを攻撃対象の決定へ切り替え、生存中の敵だけを強調する。対象選択の補助ボタンとキーボード操作は残す。

### 導線と状態

- 通常戦：依頼選択 → `battle`（敵1体） → 結果。
- 三つ巴：依頼選択 → `battle`（敵A/B） → 技選択 → 対象選択 → 結果。
- 乱入：通常戦の2〜4ターン目 → 三つ巴表示へ切替 → 以後は三つ巴と同じ操作 → 結果。
- 選択中の敵が行動前に倒れた場合、先頭の生存敵へ自動切替する現在の安全策を維持する。
- 敵の行動先は現行どおり無作為。敵対値、優先対象、かばう、契約対象保護は追加しない。
- 範囲攻撃は追加しない。すべての攻撃技は単一対象として扱う。

## 4. フェーズ2の固定仕様：錬成UI案B

既存の3画面構成を維持し、入力画面の上から下を次の順に揃える。

1. 狙う錬成対象と通常／指定の選択
2. 消費するモンスター
3. 素材
4. コインまたは指定錬成の固定消費
5. 成功率内訳、失敗時候補、最低保証、残響
6. 消費内容を確認するボタン
7. 最終確認と結果

投入個体・素材・コイン・残響の不可逆消費は、入力画面と最終確認の両方で明示する。候補0体、所持不足、パーティー編成中、遠征中、ロック中、最後の所持モンスターは、実行前に理由を示して止める。失敗時は既存どおり消費前の安全な画面へ復帰できるようにする。

## 5. チュートリアルの境界と保存仕様

### 初回必須チュートリアル（フェーズ4）

新規セーブで一度だけ、5〜10分を目安に以下の基本循環を実画面で案内する。

1. 短い導入（案内役グノーシス、プレイヤー呼称は「契約者」）
2. ホームから最初のクエストへ進む
3. 技または攻撃、HP・属性・ターンを知る
4. 撃破後に経験値・コイン・素材を受け取る
5. 契約を一度体験し、編成・モンスター画面を見る
6. 次の成長目標を示してホームへ戻る

新たな章・人物・敵・イベントを作ることは、このロードマップの対象外とする。

### 機能別の初回案内（フェーズ5）

三つ巴、乱入、錬成、遠征、進化・融合、特殊条件の討伐、黄金郷、図鑑、ショップ・アイテムで、初使用時に短く表示する。三つ巴では「敵同士も攻撃する」「技の後に対象を選ぶ」「契約候補が敵に倒されることがある」までを説明する。将来拡張の3要素は説明しない。

### 追加する保存フィールド（フェーズ3）

`mb_v95c`と既存フィールドは維持し、次だけを追加的に正規化する。

```js
tutorialVersion: 1,
tutorialStep: 0,
tutorialCompleted: false,
tutorialGuides: {
  threeWay: false,
  invasion: false,
  alchemy: false,
  expedition: false,
  evolutionFusion: false,
  specialHunt: false,
  goldenLand: false,
  dex: false,
  shopItems: false
}
```

- 新規セーブは`tutorialCompleted: false`で開始する。
- 既存セーブは移行時に`tutorialCompleted: true`とし、初回必須チュートリアルを強制しない。
- 既存プレイヤーはメニューから開始・再開・再閲覧できる。
- スキップは確認を要求し、途中進行は`tutorialStep`で再開できる。
- 戦闘途中や錬成途中の一時UI状態は保存しない。
