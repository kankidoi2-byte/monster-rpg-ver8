# 制作ロードマップの区分と現在地

更新日：2026-09-03
基準ブランチ：`main`

## この文書の目的

このリポジトリでは複数の作業計画で「Phase」という呼称を使っている。進捗の二重計上や、別計画のPhaseを次工程と誤認することを防ぐため、次の3系統を分けて管理する。

1. 総合監査・改善計画
2. 本編チュートリアル完成ロードマップ
3. ゲーム制作自動化サイクル

PR名やブランチ名に含まれる「Phase」は、それだけでいずれかの計画へ計上しない。下記の対応表と各計画の進捗記録を基準に判断する。

## ゲーム制作自動化サイクル

## 運用ルール

- 進捗更新時は、計画名、Phase番号、対応PRまたはコミットを必ず併記する。
- 別計画の完了を流用して進捗率を上げない。
- 保留中または定義未確認のPhaseは、仕様を復元・合意するまで実装へ進めない。
- 一般機能のPRに独自のPhase番号が付いていても、対応する計画名またはCycle番号がなければ別作業として扱う。
- ゲーム制作自動化では通しPhase 64以降を作らず、制作目標ごとにCycle番号を増やしてPhase 1〜5を再使用する。
