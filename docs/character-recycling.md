# キャラクター重複個体の活用

2026-09-05 決定・実装。ユーザーは設計から公開まで承認済み。

- 重複は別UIDの所持個体として保持する。初入手の形態（既存monster ID単位）は自動ロックする。
- 既存セーブは各形態の配列先頭個体を一度だけロックする。過去の取得時刻は保存されていないため、現存する個体の順序を使う。既存のロックを解除しない。
- `saveMeta.migrations` の `character_first_lock_v1` で適用済みを記録し、手動解除後は再ロックしない。保存キー `mb_v95c`・UID・図鑑IDを維持する。
- 全キャラクター形態を錬成触媒として許可する。補正・消費条件はモンスターと共通。錬成の完成候補には追加しない。
- 所持一覧の「育成・個体情報」から個体を消費し、経験値アイテムと既存通貨のコインを同時に付与する。レベル・投入した育成資源による払い戻しは行わない。
- ロック中・パーティー編成中・遠征中は錬成も変換も不可。全所持個体の最後の1体も不可。
- 同一形態の最後の1体は、ロック解除済みなら追加確認後に消費可能。錬成の確定時と変換の確定時に確認する。
- 変換は報酬プレビュー→確認→必要なら最後の1体の追加確認→再検証→消費・付与→保存。保存失敗時は消費前のメモリ状態へ戻す。再実行時はUID不在を検出し報酬を重複付与しない。
- 所持個体の装備参照だけを消し、図鑑の入手記録と所持技カードは保持する。

現行排出はエルナ★1、ステラ★2、ルミナ★2。ガチャの対象・確率・費用は変更しない。報酬は `js/data.js` の `CHARACTER_RECYCLE_REWARDS` に集約する。

## 検証

`npm run check` に `check:character-recycle` を追加。自動ロック・10連重複・錬成資格・出力除外・ロック/編成/遠征保護・キャンセル・最後の1体・報酬・二重実行・保存失敗・旧セーブ移行・再読み込み・所持一覧描画を検証する。

ローカルの確認用ブラウザは接続拒否・タイムアウトのため使用できなかった。Android/Chromebook実機での画面確認は未実施。自動テストの成功を実機確認済みとは扱わない。
