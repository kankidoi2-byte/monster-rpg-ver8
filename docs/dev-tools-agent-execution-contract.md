# 自動点検エージェント実行契約

## 位置付け

この文書は、Phase 23〜32の自動点検エージェントが従った安全境界と、Phase 33以降の制作自動化への移行関係を定義する。機械可読な正本は `docs/dev-tools-agent-execution-contract.json` とする。制作作業のリスク別承認は `tools/game-production-orchestrator/risk-approval-contract.json` を正本とする。

契約にない操作は許可しない。取得不能、未確認、判断不能を成功として扱わず、停止して記録する。

## 許可する操作

- リポジトリ、PR、Issue、CI、GitHub Pagesの上限付き読み取り
- 安全な診断要約の読み取り
- 宣言済みローカルテストと未投稿分析の実行
- 1 Phase専用ブランチへの進捗チェックポイント記録

Phase 24〜32では段階的に点検機能を有効化した。Phase 33以降は、検証済み低リスク作業に限り、専用ブランチ、コミット、push、PR、安全なマージ、Pages自動公開の確認まで個別確認なしで進められる。判定不能時は許可しない。

## 明示承認が必要な操作

- GitHub Issue投稿は、投稿対象ごとに新しい完全一致の確認を必要とする。過去の承認は再利用しない。
- エージェントが生成したブランチとPRは、Phase 33のリスク契約が低リスクと判定し、停止条件がなければ作成ごとの確認を不要とする。
- トークン、OAuth、権限設定、Android・Chromebook確認、危険または手動のマージ、手動公開と公開設定変更は個別承認を必要とする。

安全条件を満たした低リスクPRのマージと、それに伴うGitHub Pages自動公開・公開後確認は条件付き包括承認の対象とする。CI未観測、競合、重大な曖昧さ、セーブ・ID・破壊的変更などの承認フラグがあれば停止する。

## 禁止する操作

- `main`への直接書き込み、force push、履歴改変
- セーブキー`mb_v95c`、既存IDの意味、既存セーブ項目を壊す変更
- 秘密情報、トークン、Cookie、APIキーのコミットまたはログ出力
- 未承認のIssue・メッセージ投稿、workflow操作、公開設定変更、権限拡大
- 課金、購入、有料サービス有効化、無制限リトライ
- 無関係な削除、未観測テストの成功扱い

## 上限

1回に扱うのは最大1 Phase、同一PhaseのPRは原則1件、修正試行は1トリガーにつき最大1回とする。コミットとworkflow runは各20件、ブランチ・PR・Issue・jobは各100件、jobのstepは100件、診断エラーは20件までに制限する。

通信先はGitHub API、GitHub、対象GitHub Pagesの固定ホストに限定する。上限超過が必要なら自動拡大せず停止する。

## 停止条件

CI失敗または未観測、競合、必須テスト不明、重大な仕様曖昧さ、認証・権限・レート制限、秘密情報検出、セーブ互換性リスク、破壊的または無関係な差分、実機確認、Phase 33リスク契約が許可しない外部書き込み、費用または権限拡大が必要な場合は停止する。

停止時は危険な変更や無制限再試行を行わず、原因、確認済み事項、必要な最小操作、次の開始地点を記録する。

## 費用規則

明示承認なしの直接費用上限は0米ドルとする。購入、課金設定、有料サービス、請求変更を自動実行しない。費用が必要になった時点で停止して承認を求める。

## ログ規則

機械可読な進捗、人間向けロードマップ、専用ブランチのコミットまたはPR、テスト・CI結果、次の開始地点を残す。長い処理前と有意な作業単位の後にチェックポイントを作る。

秘密情報、API生レスポンス、診断JSON全文、自由入力の個人情報は記録しない。固定形式へ正規化した上限付きメタデータだけを保持する。

## Phase 33移行の完了条件

- 機械可読契約と本文書が一致する。
- 許可、承認、禁止、上限、停止、費用、ログ、互換性の規則を専用テストが検証する。
- Phase 23〜32の点検境界を維持し、低リスク制作書き込みだけをPhase 33契約へ委譲している。
- ゲーム本体、セーブ、既存ID、プレイヤー向けUIを変更していない。
- `npm run check`、PRのCI、マージ後CI、GitHub Pages公開を確認する。

`js/notices-data.js`は更新しない。契約文書と検証だけで、プレイヤーから見える変更がないためである。
