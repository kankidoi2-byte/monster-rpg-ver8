## 保存の構成

`save.gBless = {v:1, on:false, weekKey:'YYYY-MM-DD', week:100, reserve:0}` を追加。週境界は端末のタイムゾーン設定に依存せずJSTで求める。

勝利の加護判定・報酬計算・消費は既存の仮セーブ候補の中で行い、既存の `commitSaveMutation` で一度だけ確定する。保存再試行は同じ候補を使い、再抽選・二重消費しない。保存待ちの間はチップからの操作・タイマー更新による候補変更を防ぐ。

黄金郷の `huntRewardAmount` を通る通常コイン報酬は倍率対象。既存の固定黄金郷ボーナスは据え置き、結果画面には「＋固定報酬」と内訳を含む前後の総額を表示する。

## 検査コマンド

- `npm run check:g-bless`: ロジック・保存失敗・受取・ブラウザー・縦画面の受け入れ検査。
- `npm run check`: 全体検査の実行結果はPR本文に記録する。
- 既存のプレゼントBOXブラウザー検査でタイトル→ホーム→編成→依頼選択→戦闘開始→保存を確認。専用検査でも同じ導線から勝利処理・報酬表示・再読み込みを確認。

スクリーンショットの出力先は環境変数 `G_BLESS_EVIDENCE`（既定 `/tmp/g-bless-qa`）。
