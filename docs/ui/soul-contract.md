## 実装
`soul-contract.js` は確定済みの result を表示するだけで、通貨・獲得・保存にアクセスしない。body直下の専用overlayにCanvas星空とDOM/CSSの契約書・画像・名前を配置し、白黒テーマから分離。
100個の固定背景星、描画30fps上限、DPR1.5上限。Canvas初期化失敗時は静的な同色の星空へフォールバック。描画時以外の待機、非表示ページで描画休止、終了時のRAF/timer/event/DOM/inert/overflow/focusを復元。
単発は1魂、10連は10魂同時発光。各結果の順を維持し、最初と★3は長めの刻印・溜め、通常の連続結果は短縮。★3のみ金色。現在の15排出形態は★1〜3で、★4/5演出は追加していない。
異世界文字は独自SVG線画で、現実の文章をフォント変換していない。紙面の段階刻印、金色の面に走る光、短い解放光と240msの小振幅揺れ。reduced-motion時は揺れ/閃光/Canvas連続描画を省き、確定結果を維持。
画像はIMG registryの最新背景付き素材、名前/レアリティは実データ。下部星は契約成立順に点灯。スキップ/Escape/画面遷移は確定結果へ終了。音量・ミュート・音声再生の既存機構が存在しないため無音を維持し、新たな音声設定は設けない。

## 保存・復帰
キャラクターガチャは元の抽選関数を利用し、取得に伴う図鑑・技カード・ランク経験値を含むsave全体をステージング。獲得とreceiptを同じ既存保存キーへ1回commitし、成功後のみ演出開始。失敗時は元のsaveへ戻す。
追加フィールド soulContractReceipt は未存在なら通常状態。version/id/count/cost/ordered entries(unitId/instanceUid/isNew/locked)のみ保存。所持個体をreceiptから再生成しない。結果を見て次を引くか、確認ボタンで記録を消去するまで、再読み込み後も入口で結果を復元できる。
キャラクター契約と結果確認の書込みは、プロフィール別のWeb Locksでタブ間を直列化し、ロック取得後に既存保存の競合を再確認する。Web Locks非対応ブラウザでは安全のため新規契約を拒否する。この直列化は当機能の協調する契約・確認処理が対象で、既存の他機能の全保存処理を非同期化する変更ではない。
演出中の連打は拒否。保存済みの未表示receiptがあれば最初に結果を表示し、新規課金しない。プロフィールごとの既存保存keyを維持し、演出中の切替を拒否。ランクアップoverlayは契約終了まで待機。

## 混在タブの保存競合と手動復旧
通常の同期保存と契約の同時実行では、通常保存の最終照合後に契約が入り、古い保存が主データを上書きする競合を再現した。全機能の非同期化は行わず、契約前後の完全セーブをプロフィール別の `mb_v95c_soulContractRecovery_v1` / `mb_v95c_profile2_soulContractRecovery_v1` へ独立保存する。主保存直前に復旧記録の永続化・読戻しが成功しない場合は契約を拒否する。
主セーブの `soulContractAppliedId` と記録を照合し、相違があれば新しい契約を停止する。現セーブと契約前・契約時のデータを書き出せるが、自動復元・自動マージ・仲間の再付与はしない。通常の育成・進化・再生などで元の個体UIDが消えても、正常な取引マーカーが続いていれば競合扱いにはしない。
復旧記録は端末内のみで、外部へ自動送信しない。セーブ全体を含むため、書き出したファイルは通常のセーブと同様に保管・共有先に注意が必要。保存容量を追加消費し、容量不足時は新規契約を拒否する。記録は最新契約を保持し、処理中は直前記録を1世代だけ含める。有効な新規契約が確定した後は最新記録へ縮め、無制限に履歴を増やさない。
別端末への正当なセーブ取込みでは端末内記録がない。主セーブとメモリのマーカーが一致し、復旧記録が本当に存在しない場合だけ、明示確認でそのセーブを端末の基準に設定する。主セーブ・所持・通貨は変更しない。既存の破損・競合・失敗記録をこの操作で消すことはできない。
残る制約：通常保存を含む全タブの自動直列化ではない。競合時の2つの進行を自動統合しないため、書き出したデータを確認した上で既存のインポート手順による手動選択が必要。実機Android/Galaxyでの負荷と操作確認は未実施。
