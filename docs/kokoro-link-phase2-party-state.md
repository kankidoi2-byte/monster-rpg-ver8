# ココロリンク Phase 2：通常パーティー内リンク管理

状態：実装完了  
対象：リンク候補判定、使用済み管理、戦闘ライフサイクル  
プレイヤー向け挙動：発動UI未接続のため変更なし

## 1. 正式なパーティー構成

ココロリンク専用の追加編成は作らない。従来の通常パーティー3体だけを使用する。

```text
通常パーティー3体
├─ 現在戦闘中：1体
└─ 控え：2体（ココロリンク候補）
```

合計6体にはせず、セーブデータやパーティー編成画面にも別枠を追加しない。

## 2. 確定ルール

- 現在戦闘中の個体は自分自身へリンクできない。
- 控えのモンスターは1体につき、1戦闘で1回までリンクできる。
- 控え2体はそれぞれ別のタイミングで使用できる。
- リンク使用後も、その個体は交代して戦闘へ出られる。
- 戦闘不能の個体はリンクできない。
- 使用済み個体が控えに戻っても再使用できない。
- 交代後は現在の戦闘個体を除外し、残りから候補を再計算する。
- 勝利、敗北、逃走、次の戦闘準備で使用履歴をリセットする。
- キャラクターは現時点ではモンスター用ココロリンクの対象外。

## 3. 実装

`js/kokoro-link.js` に戦闘中だけ存在する `kokoroLinkBattleState` を追加した。セーブデータには書き込まない。

### 主な処理

- `resetKokoroLinkBattleState()`：使用済みUIDを初期化
- `kokoroLinkBattleSnapshot()`：現在の使用状態を安全に取得
- `listKokoroLinkSources()`：パーティーと現在位置から候補を算出
- `currentKokoroLinkSources()`：実戦中の `partyBattle` から候補を取得
- `canUseKokoroLinkSource()`：指定UIDを使用できるか判定
- `markKokoroLinkSourceUsed()`：候補を戦闘中使用済みにする
- `markCurrentKokoroLinkSourceUsed()`：現在のバトル状態で使用済みにする

## 4. 候補判定

候補になるには、次の条件をすべて満たす必要がある。

1. 通常パーティー内に存在する
2. 現在戦闘中の位置ではない
3. 個体UIDが有効
4. 同じUIDが候補内で重複していない
5. 戦闘不能ではなくHPが1以上
6. モンスター個体である
7. その戦闘でまだリンクを使用していない

候補にはPhase 1のリンクプロフィールも付与されるため、Phase 3では再計算処理を増やさず、そのまま予測効果表示と発動へ利用できる。

## 5. 交代との関係

リンク使用は個体のHP、戦闘不能状態、パーティー位置を変更しない。そのため、使用済みの控えも通常どおり交代出撃できる。

交代後はアクティブ位置だけを基に候補を再算出する。例えば最初の戦闘個体Aが控えへ移った場合、Aが生存かつ未使用なら新しいリンク候補になれる。

## 6. 戦闘形式との共通化

候補判定は敵側の構成に依存せず、味方の `partyBattle` と `activePartyIdx` だけを使用する。そのため、以下で同じ処理を利用できる。

- 通常戦
- 三つ巴戦
- 乱入戦
- ボス戦
- 黄金郷

通常戦用と三つ巴戦用で、候補判定や使用回数を別実装にはしない。

## 7. リセット地点

- `prepareBattleParty()`：新しい戦闘準備
- `endPartyRecovery()`：敗北または戦闘結果から離脱
- `runAway()`：通常戦から逃走
- `win()`：通常戦勝利
- `runAwayFromMultiBattle()`：三つ巴・乱入戦から逃走
- `winMultiBattle()`：三つ巴・乱入戦勝利

複数地点で安全に呼び出せる初期化処理とし、二重リセットでも問題が起きない。

## 8. 自動検証

`scripts/test-kokoro-link-party-state.mjs` で次を確認する。

- 1体が戦闘中なら控え2体が候補になる
- 1個体につき1回だけ使用できる
- 使用しても個体の戦闘情報が変化しない
- 使用済みでも交代出撃を妨げない
- 交代後に候補が再計算される
- 戦闘不能と使用済み個体を除外する
- リセット後に再び候補になる
- キャラクターを除外する
- 重複UIDを二重候補にしない
- 不正なアクティブ位置では候補を返さない
