# ゲーム制作自動化 v1 ロードマップ

## v1完成状態

ゲーム制作自動化システムv1は完成済みである。完成日は2026年9月3日（日本時間）。

v1は、ユーザーが司令塔へ1件の制作目標を渡した後、目標のPhase分け、システム／コンテンツラインへの割当、独立ブランチでの実装、専用検査、PR、CI確認、安全なマージ、GitHub Pages公開、公開後点検まで進め、作業完了後に両ラインを停止する。

マップ図鑑「生態系」の試運転（PR #125〜#127）で、この一連のサイクルが本番環境まで完走することを確認した。

次々とバックログを選んで無期限に制作する機能と、大規模機能・物語方向をAIが独立判断して制作する機能はv1に含めず、将来のv2候補とする。

## 目的

旧Phase 0〜32は、診断、状態把握、異常調査、安全な修正案生成までの「点検自動化」を完成させた。旧Phase 33〜38は、その基盤を使い、ユーザーが指定した制作目標を実装、検査、PR、統合、公開後確認まで進めて停止する「制作自動化v1」を完成させた。

機械可読な正本は`docs/game-production-progress.json`、リスク別承認の正本は`tools/game-production-orchestrator/risk-approval-contract.json`とする。

## 点検自動化と制作自動化の差

| 項目 | Phase 0〜32 点検自動化 | Phase 33以降 制作自動化 |
|---|---|---|
| 起点 | CI、Pages、診断の異常 | ユーザーが指定した1件の制作目標 |
| 主目的 | 原因を特定し安全な最小修正案を作る | ゲーム本編へ新しい機能・内容・演出を届ける |
| 次作業 | 状態コードから確認対象を提示 | 指定目標を依存関係、効果、リスクからPhase分けする |
| 実装 | 限定された障害修正案 | システム／コンテンツの独立ラインで実装 |
| 書き込み | 案件ごとの確認後にPR化 | 低リスクはブランチ、PR、安全なマージまで自動 |
| 完了 | レポートまたは修正PR | main、Pages、公開ゲーム確認、進捗記録、両ライン停止 |

## 基本構成

### 制作司令塔

最新main、AGENTS.md、進捗正本、バックログ、PR、CI、Pagesを確認する。ユーザーが指定した目標を、依存関係、プレイヤー効果、作業リスクから必要なラインへ割り当てる。同じファイル・機能を触る作業は直列化し、各作業の完了条件、専用テスト、`npm run check`の要否、お知らせ要否、完了後の停止条件を開始前に固定する。

### ゲームシステムライン

機能、不具合、セーブ互換性、UI、戦闘、各種機能、演出基盤、スマホ対応、テスト、性能を担当する。最新mainから専用worktreeとブランチを作り、原則1作業1PRとする。

### ゲームコンテンツライン

ストーリー、会話、キャラクター、モンスター、マップ、アイテム、技、敵編成、報酬、演出仕様、図鑑説明、バランス、設定整合を担当する。既存IDの意味や主要設定を変えず、加算的な内容を優先する。

統合直前だけ一時的なQAレビューを行う。恒常的な第4ラインにはしない。

## v1完成条件

- ユーザー指定の目標をPhase、担当、依存関係、受入条件、リスク、停止条件へ分解できる。
- システムラインとコンテンツラインを最新mainから別worktree・別ブランチで実行できる。
- 専用検査と必要な`npm run check`を実行し、未確認結果を成功扱いにしない。
- 低リスク変更を個別確認なしでコミット、PR、CI修正、安全マージ、Pages公開、公開後点検まで進められる。
- 確認必須条件では停止し、ユーザーへ必要最小限の判断を求める。
- 進捗正本へ結果と再開地点を残し、完了後は次の仕事を自動選択せず停止する。

## リスク別承認

低リスク作業は、調査、設計、バックログ更新、独立ブランチ／worktree、実装、検査、コミット、push、PR、限定的CI修正、安全条件を満たすマージ、Pages自動公開、公開後点検まで個別確認なしで進める。

セーブ構造・移行、`mb_v95c`、既存ID・図鑑番号の意味、データ消失、主要ルール・物語設定、好みで結果が大きく変わる判断、実機確認、秘密・権限・費用、Issue・外部メッセージ、破壊的変更、公開設定、CI失敗／未観測、競合、重大な曖昧さは停止して最小限の確認を求める。

## 次回の開始方法

ユーザーが司令塔へ、次に完成させたいゲーム本編の目標を1件指定する。司令塔はその依頼を`Cycle 5 / Phase 1`から始まる新しい単発制作サイクルとしてPhase 1〜5へ分け、必要なラインだけを起動する。以後は目標ごとにCycle番号だけを増やし、Phaseは毎回1へ戻す。バックログにあるアイテム／キャラクターガチャ演出、チュートリアル添削、第1章制作などは候補であり、自動着手しない。

## v2候補（v1には含めない）
