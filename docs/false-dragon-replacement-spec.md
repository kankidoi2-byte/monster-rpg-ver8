# 偽竜Beta／Gamma置換：現行仕様・互換性・残課題

確認日: 2026-09-21。基準main: `6cd3d7b8f755295a52c7bdb8e0685274612f99cf`（PR #215）。

## 判定と仕様の範囲

**内部ID・旧no・固定技IDを保持する方式を現行の正式な保存互換方針とする。**
ただし「技構成まで矛盾なく完成」「旧装備をすべて維持」とは判定しない。属性変更によって4件の光技が本人に装備できず、敵と味方で使える技が異なる。これは表示名の修正だけでは解消しない実質的な仕様上の残課題であり、以下に明記する。本同期は現行動作の記録と検査で、ゲーム性能・装備ルール・演出・セーブ処理を変更しない。

## 保存互換の実際の境界

`js/save.js`の`parseAndPrepareSave`は既存IDを認識するため、所持個体、UID、レベル、経験値、ロック、所持記録、パーティー、固定技カードを保持する。保存キーは`mb_v95c`。表示番号の変更による初期化はない。

一方、`js/core.js`の属性／身体条件と`js/skills.js`の`ensureInstanceSkills`は現行モンスターの条件で装備を再検査する。

- 旧光技4件は所持カードとして残るが、火／森の本人からは外れる。他の条件を満たす光属性モンスターへ装備可能。
- 既存技カード所持数移行済みのセーブでは、解除されたカード枚数も保持される。移行前の非常に古いセーブには、従来からの`equipped_skill_cards_v1`（装備枚数を基準に在庫を再構築）が適用される。「全世代のカード数が無条件で同一」とは保証しない。
- ★5→★4によりCOST上限は同レベルで2低下（Lv.1: 10→8、Lv.100: 43→41）。属性・身体・コスト条件に違反する旧装備は解除され得る。Gammaは翼タグも失っているため、他の翼条件付き技も対象となる。
- 本人の現行初期装備はBetaが02（翼撃）、Gammaが02（咆哮）の各1技。敵は元の`moves`から選ぶため光技も使う。味方は火／森・無属性の適合カードを追加装備できる。
- `no`は30／31を保持し、図鑑は`dexNo`39／40を表示する。旧ID削除・新ID移行は行わない。

### 修正の優先順位

1. **表示修正案を優先**：内部ID、技ID、属性、威力、COST、効果、確率、装備条件を保持し、旧偽竜名を表示から外す。上の名称は候補であり未採用。技カードは他種も使うので本人専用に見せすぎない。
2. **単なる配列の名前置換は危険**：`legacySkillIdFromMove`は名前由来の旧IDを生成し、`skillFormFor`／`skillRequirementsFor`も名前の正規表現で演出・装備条件を導出する。表示名を別に持つか、旧名のaliasとID別の演出・条件を固定してから変更する。固定IDを維持するだけでは十分でない。
3. **性能は別判断**：既存6技を火・森へ変えると、他の所持者の装備可否・相性・ダメージまで変わるため表示修正には含めない。旧6技を残して本人向けの新技を足す案も、200技の件数・抽選・バランスを変える別仕様。光技の使用を特例許可する案も装備ルール変更となる。

旧装備を完全保持し、本人が従来3技を使えることまで必要なら、技仕様の判断を先に行う。現状の保存方式を採用することと、戦闘設計を完成扱いすることを混同しない。

## 採用されなかった過去案・履歴

旧案「Beta／Gammaの旧IDと各3件、合計6件の技を削除し、完全に新規の2体へ置換する」は、現行方式に採用されなかった案として残す。現在の実行待ち作業ではない。過去の計画書・監査・技一覧は当時の証跡であり、一括削除・過去への書換えはしない。将来再検討するときは新規IDと明示的な保存移行、旧カード処理、イベント、全件数の設計が必要。
