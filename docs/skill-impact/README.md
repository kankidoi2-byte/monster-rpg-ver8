## 調査結果と対応

- [全202行の対応一覧](coverage.md) / [機械可読JSON](coverage.json)。登録200技＝攻撃160・補助40（うち旧装備互換34技）。原モンスターの技配列も全件対応。
- 既存の技種別演出125技、汎用攻撃35技、効果別共通補助40技。既存200技はすべて演出ありであり、これらを「新規補完」として数えない。
- 通常攻撃だけ発動演出がなく、被弾表示へ直行していた。意図的に簡素な240msの共通打撃を追加（命中91ms）。
- debuffは現行登録技には存在しないが、既存戦闘処理が対応する互換経路。演出未対応と使用者側の座標指定を修正し、対象に下降矢印（360ms、命中173ms）。新技・新ID・排出対象は追加しない。
- repeat_attackの2撃目は計算・HP結果ラベルのみで、独立した技モーションや被弾がなかった。同じ技の2回目の発動・命中・被弾・HP更新を順に表示。1撃目で撃破した場合は従来どおり追加しない。
- 自己回復、防御、強化、水の盾は使用者、眠り・弱体化は相手へ。敵→味方・敵→敵も同じ座標計算を使用。

## タイミングの変更

`playBattleSkillMotion(...,{untilImpact:true})`はCSSの接触キーフレーム時点で戻り、戦闘処理が結果を確定する。`battleHpResult`で数値・HPバー・HP文字を同一処理内で更新する。残りの演出は`finishBattleSkillMotion`で回収してから次へ進む。既存3引数の呼び出しは従来どおり演出完了まで待つ。

| 代表技種 | 旧・結果表示 | 新・結果表示 | 演出全長 |
|---|---:|---:|---:|
| 牙 | 400ms | 168ms | 400ms |
| 爪 | 380ms | 106ms | 380ms |
| ブレス | 430ms | 138ms | 430ms |
| 突進 | 460ms | 294ms | 460ms |
| 雷撃 | 440ms | 194ms | 440ms |
| 回復 | 500ms | 225ms | 500ms |

CSS本体と疑似要素のdurationをJSと共有し、翼・脚など共通CSS側とJS側で異なっていた全長も揃えた。従来の末尾120ms待機を除去。2撃目を見せるための追加攻撃以外は、不必要な待機を足していない。フレームの実際の描画には端末負荷・リフレッシュレートによる誤差がある。

戦闘の開始・行動境界・手動/強制交代・単体/複数敵レイアウト切替・次ウェーブで、登録した一時ノード/タイマー/クラスを回収。同じ対象への次の被弾は前の被弾を片付けてから開始し、古いタイマーで新しい被弾が消えないようにする。

減動設定では技移動・点滅を省き、結果文字・HP・状態・履歴を保持。毒・反動・吸収・混乱自傷の既存結果ラベルは維持する。

## プレビュー

`node scripts/build-skill-motion-baseline.mjs`で基準mainの描画コードを`review-baseline/`に出力し、`npm run dev`で起動。`docs/skill-impact/preview.html`を開く。生成した基準コードはgit管理外。比較ページは同じ本編のCSS・技分類・描画関数を読み込む。

比較サンプルは固定ダメージ24/回復27、追加攻撃確定。実戦の乱数・威力の再現ではなく、見た目・対象・更新のタイミングを見るもの。確認版ゲームへのリンクも同梱する。比較ページのコードは本編indexから読み込まず、セーブにも触れない。

スマホで通常攻撃→火炎牙→ブレス→ライトニングチェイン→自己回復を比較し、敵A→敵Bと減動を切り替える。本編で撃破→次の敵、手動交代、強制交代を確認する。
