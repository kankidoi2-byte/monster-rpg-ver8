# UI再設計：改修前基準

この文書は、UI再設計ロードマップのフェーズ0で固定した改修前基準である。UIを刷新しても、ゲームロジック、既存セーブ、確定済み仕様を意図せず変更しないために使用する。

- 基準ブランチ：`main`

- 公開先：GitHub Pages
- セーブキー：`mb_v95c`（変更禁止）
- 対象端末：Android、Chromebook、PC幅

## 現行画面

改修前の現行版には19個の`section.screen`がある。新UI移行では、機能を整理するための育成ハブとその他メニューを追加し、互換画面を残したまま段階的に移行する。

- ホーム
- 遠征
- 進化
- パーティー設定
- 討伐依頼選択
- 戦闘用アイテム選択
- 契約書確認
- 戦闘
- 合成
- 錬成
- 錬成確認
- 錬成結果
- ショップ
- アイテムガチャ
- 手持ち
- 技変更
- 属性相性
- モンスター図鑑
- アイテム図鑑

起動画面とボスCAUTION演出は`section.screen`とは別のオーバーレイとして存在する。

## 現状の構造的課題

- 12個の機能が上部メニューへ同じ重要度で並んでいる。
- ホームが冒険拠点ではなく、説明と機能入口の一覧になっている。
- 主要画面のDOMが`index.html`へ集中し、インラインスタイルとインラインイベントが多い。
- UI描画は複数のJavaScriptファイルから`innerHTML`で行われ、表示とゲームロジックの結合が強い。
- スマートフォン向けCSSは縮小と列数変更が中心で、画面内の優先順位そのものは変わらない。
- 戦闘ではマップ、敵味方カード、コマンド、ログが縦に積まれ、操作までスクロールが必要になる。
- 暗い青紫の汎用パネルが全画面で共通し、起動画面の明るい王道ファンタジー感と差がある。

## 保護する契約

- 既存のモンスター、アイテム、技、マップ、レシピ、個体UID、図鑑番号を変更・再利用しない。
- 初期5体のIDを維持する。
- 既存セーブフィールドを削除しない。追加時は安全な既定値と加算型移行を用意する。
- 戦闘、三つ巴、乱入、難易度、錬成、遠征、黄金郷の確定仕様を維持する。
- 起動画面のロゴ、背景、モンスター演出を新UIでも維持する。
- UI移行中も全主要機能へ到達できる互換導線を残す。

## 自動検査

`scripts/test-ui-contract.mjs`で以下を確認する。

- セーブキーの読込・保存・削除
- 初期5体のID
- 現行19画面と、移行用に追加したハブ画面
- 戦闘・編成に必要な主要DOM ID
- 起動画面の画像フック
- JavaScriptファイルの存在と読込順

既存のデータ、画像、三つ巴、遠征、黄金郷の検査と合わせ、変更後は`npm run check`を実行する。

ロードマップ全体を、想定作業量に応じて次の100ポイントで管理する。各フェーズ内は、完了した作業項目の割合で加算する。

- フェーズ1 UX構造・ワイヤーフレーム：12%

- フェーズ3 共通枠・ホーム・ナビゲーション：14%
- フェーズ4 戦闘UI・演出の中核改修：25%
- フェーズ5 討伐依頼・モンスター関連画面：11%
- フェーズ6 育成・錬成・遠征・その他機能：9%
- フェーズ7 報酬・音・動きの磨き込み：6%
- フェーズ8 全体検証・公開移行：5%
