## 実装

- 錬成：別プロフィール/別タブに直接旧snapshotを書き戻していた処理を撤去。未コミットだけメモリrollback。保存後の描画失敗は獲得結果を保持。待機前プロフィールを保存して再照合、同じplanの二重完了を拒否。
- 1対1契約：消費だけ先に保存する処理を廃止し、消費・加入・図鑑・契約者経験値を1回の主セーブへ。複数体契約も保存失敗を確認し、候補と消費を維持。実行中と試行済みの二重呼出を拒否。
- ショップ/アイテムガチャ/合成・特殊進化/遠征受取：保存失敗なら全メモリを復元して成功表示しない。保存後のUI例外では結果保持と再表示案内。
- rollback時はactiveInstance、partyBattleの個体参照、進化待ちキュー、修復レポートを整合させる。一時ゲストは維持。
- インポート/バックアップ復旧：置換前の耐久退避と通常backup成功を必須化。file.text待機中プロフィール変更で中止。
- 価格・確率・技/個体/素材ID・既存セーブキー・既存JSONフィールドは変更しない。

## 読込・復旧用の追加記録

`mb_v95c_replacement_recovery_v1`（枠2は既存key resolverによる `mb_v95c_profile2_replacement_recovery_v1`）。通常セーブのJSON形式に新フィールドは追加しない。

置換前primary（before）、元backup（backupBefore）、正規化された置換後候補（after）を文字列のまま一緒に保存し、読み戻して一致確認後にbackup/primaryを更新する。3つのセーブ相当＋JSONエスケープ分の容量を使う。容量不足なら置換を中止する。

- pending：中断/保存失敗/完了表示更新失敗を含む。次の置換は停止。現在のprimaryは自動で置換しない。
- completed：primary書込成功後。記録を残し、次の承認された読込・復旧で置き換える。
- acknowledged：記録全体の書出操作後、プレイヤーがファイル保管と次回置換を確認した状態。主セーブは変えない。次回の読込・復旧で記録が置き換わる。
- malformed/別プロフィールの記録：通常の置換・確認済み操作は拒否。生の記録全体のexportはできる。破損記録を黙って削除しない。
- 完了状態の書込に失敗してもprimaryの成功を取り消さない。pendingの両候補は残る。

セーブ管理に状態と5つの操作（記録全体、置換前、置換後候補、元backupの書出、確認済み）を用意。個別候補ファイルは通常のセーブ読込で使えるJSON。記録全体のファイルは保存資料であり、そのまま通常インポートする形式ではない。個別候補を書き出しただけでは記録の上書き許可にならない。

記録は同じブラウザのプロフィール別localStorageだけに保存し、送信やanalytics連携は追加しない。書出ファイルにはプレイヤー名・所持/進行データ等のセーブ全体が含まれる。ブラウザデータ削除前にはファイルを保管する。

## 残る境界

- localStorage全writerの原子的トランザクション化はしない。同時に競合チェックを通過した旧writer同士の狭い競合を完全防止したとは言わない。今回の修正はstale拒否後の直接上書きを排除する。
- 通常/複数体契約と錬成は同じタブの同じ対象・素材の直近再試行結果を保持する。ただし別対象/別契約書/別レシピへ変更して戻る、再読込、別タブを跨ぐ結果固定は保証しない。永続抽選台帳は追加しない。
- インポート/復旧のpending記録は主セーブ更新を停止するものではない。通常プレイのセーブは可能だが、次の破壊的置換は書出・明示確認まで停止。
- 通常進化、経験値アイテム、途中帰還等、今回の実証済み4経路以外はこの修正で全解決したと扱わない。
