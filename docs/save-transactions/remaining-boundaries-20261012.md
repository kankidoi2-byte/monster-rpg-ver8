# 育成アイテム・遠征途中帰還の保存境界

## 統合状況（2026-10-18）

PR #293で #287/#288/#292/#289 をmain `81aa8cbf1c870e67d75cc6133e3da57cbfbc643d`へ統合済み。公開状況・検証証拠は[最新照合記録](../publication-status-20261012.md)を参照。以下の「未統合・未公開」「レビュー用」は初回提出時点の記録です。

参照main: `7a6fcd7f767ff72004839dcb933e117145d35189`。

保存直前の主セーブ読取失敗も中止するよう `requireReadable:true` を指定。両プロフィールで初回/保存直前の読取失敗・復元・再操作を回帰検証しています。

## 変更

- 経験値アイテム使用時の消費、経験値、レベル、進化待ちを既存 `commitSaveMutation` の中で確定する。
- 遠征途中帰還時の報酬と遠征解除を同じ境界で確定する。
- 保存できなかった場合はメモリを戻す。別タブの保存や別枠のキーは直接書き換えない。
- 保存後の表示失敗は結果を戻さず、既存の保存済み案内を使う。
- 成功時の価格・報酬・消費数・成長式・乱数配分・保存キー・保存形式は変更しない。

## 検証

`npm run check:save` の `scripts/test-save-transactions.mjs` に両枠、両機能、通常成功・主キーquota・競合拒否・保存後描画例外の16条件を追加。
失敗時の保存/メモリ維持、activeInstance/partyBattle参照と進化待ちの復元、保存再試行、消費済み操作の再実行、枠2から枠1へ影響しないことを確認する。

## 対象外

- 通常戦闘勝利の多段保存。`grantPartyExp()` 内で基本コイン/EXPが先に保存され、その後のドロップ・履歴等保存が失敗すると報酬の一部だけ残る問題を別件で実証した。今回の2経路修正では変更しない。
- 通常進化、戦闘アイテム、遠征進捗など全経路の原子化はこの変更だけで完了したと扱わない。
- 新しい草原ストーリー勝利と級別技合成は既存の原子的保存/再試行処理を維持する。
- 実機Android/Galaxyでの確認、main統合、本編公開はこのPRの完了条件に含めない。
