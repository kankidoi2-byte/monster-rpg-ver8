# 通常探索の勝利報酬の一括保存

基点: main `2ef87b73d82c9d3afae68852f6ebcaeb78b07a89`（草原全画面UI #291を含む）。
調査基準: [2026-10-12総点検資料 第5節](https://docs.google.com/document/d/1dLw3o45A3GjUZuPGJQ2oU2yLNzvxGCdowsXtpKVSGeA/edit)。本変更は独立レビュー用。未統合・未公開。

## 保存境界

- 単体・ボス・黄金郷・三つ巴・乱入・救援最終波の既存報酬処理を候補生成へ抽出。
- 生成時だけsave、遠征、進化待ち、requestを分離した候補へ適用。EXPと遠征のhelperは明示的な`saveNow:false`。全体のsaveGameの差替えはしない。
- EXP、基本/追加コイン、敵ドロップ、錬成素材、図鑑/Rank、初boss記録、勝利履歴、遠征完了時の固定報酬、世界地図の勝利/寿命/門、必要なtutorial checkpointを既存`commitSaveMutation`で主キーへ1回書込む。backup/プロフィール管理用キーへの書込とは区別する。
- 取得済み印、複数戦終了、requestの世界地図完了印、tutorial session、結果/契約/Rank/進化の表示は成功後。表示例外で保存済み報酬を戻さない。
- 保存失敗では候補をメモリに保持し、同じ候補の保存のみ再試行。プロフィール・request参照/内容・戦闘・参加UID・進化待ち・勝利前save・主キー原文を再検証。保存直前の読取失敗でも中止する。
- 未確定時は戦闘/次探索/契約/進化/プロフィール切替を停止。別タブの更新へ古いsnapshotを書き戻さない。同期再入・連打・成功後の再呼出しを拒否。

## 非変更範囲

保存キー/形式/移行、報酬数値、乱数順、ドロップ率、難易度、8ターン迅速討伐、複数戦の報酬対象、草原の独立報酬/retry、救援途中波、ステラ模擬戦、敗北/撤退を変更しない。お知らせは同ブランチに追加するが本編公開はしない。

## 検証

- 保存故障215ケース: 2プロフィール × 単体/三つ巴/乱入/boss/黄金郷/世界イベント/救援 × 遠征なし/進行/完了 × 正常/quota/読取失敗/stale/保存後表示例外、およびメモリ/request/参加UID/進化待ちの変化。
- 修正前の実勝利関数とのseed比較224ケース: 2プロフィール × 7戦闘種 × 4難易度 × 4seed。時刻/hash以外の全save、表示結果、乱数消費数が一致。
- `npm run check`、`npm run check:world-map-economy`、草原2,200戦の既存記録との一致を確認。CIはPR現headで別途確認する。
- `scripts/test-hunt-victory-save-browser.mjs`: 2プロフィール、320/360/390/430px、844px横、200%相当。実攻撃→保存失敗→同一候補retry→契約→次探索→reloadと、特殊勝利/遠征完了/救援案内の主保存1回を検証する。外部通信を遮断。CIのsave-transactionsに接続。

## 限界

候補はメモリのみ。失敗中の終了・再読込を越える復元台帳は追加しない。端末実機のGalaxy/Chromebook確認は別途必要。localStorageの全writerに対するタブ間排他ロックの導入ではない。ブラウザーの保存成功自体をOS障害から保証する変更でもない。
