# ゲーム制作効率化ツール ロードマップ

## 目的

このロードマップは、ゲーム内診断レポート、開発司令塔、自動点検エージェントを、既存ゲームとセーブ互換性を壊さず段階的に導入するための実装基準である。

進捗の機械可読な正本は `docs/dev-tools-progress.json` とする。各作業は原則として1 Phase・1ブランチ・1 PRで実施する。Phaseは番号順を優先するが、承認待ちのPhaseに依存せず最新 `main` から独立して作業できる後続Phaseは先行してよい。

## 現在地

- Phase 10「診断機能の総合検査」はPR #88、最終CI #357、Pages #130まで完了済み。
- 現在の最小未完了はPhase 18「スマホ用ダッシュボード」で、PR #85へ最新 `main` を取り込んで再検証中。
- 再検証後にAndroid確認用URLを案内し、明示承認後にマージしてPhase 19のDraft PR #86を再開する。

## 完了判定

各Phaseは次の条件をすべて満たした時点で完了とする。

1. Phase固有の成果物と専用テストが揃っている。
2. JavaScript、ゲームデータ、画像、UIを変更した場合は `npm run check` が成功している。
3. 変更差分、検査結果、残る手動確認をPRへ記録している。
4. 必要なAndroidまたはChromebook確認が完了している。
5. PRが条件付き包括承認の安全条件を満たすか、ユーザーが個別にマージを明示承認している。
6. PRが `main` へマージされ、マージ後CIとGitHub Pagesの公開状態を確認している。

文書のみ、テストのみ、またはプレイヤーから見えない変更では、`js/notices-data.js` の更新は不要とし、その理由をPRへ書く。

## 安全境界

### 自動で進めてよい操作

- リポジトリ、ブランチ、PR、CI、公開状態の読み取り
- 専用ブランチの作成
- 対象Phaseに限定した実装、テスト、文書更新
- コミット、push、PR作成、CI失敗の修正
- 進捗記録とPR説明の更新
- 必須CI成功、非破壊、互換性維持、実機確認不要などの安全条件をすべて満たすPRの `main` へのマージ
- 上記マージに伴うGitHub Pagesの自動公開と公開後確認

### 明示的な承認が必要な操作

- 安全条件を満たさない、または判断不能なPRの `main` へのマージ
- 手動公開、別環境への公開、公開設定の変更
- Android、Chromebookでの実機確認
- 破壊的変更
- 秘密情報、APIキー、OAuth、権限の設定
- 外部へのメッセージ送信、課金、購入

### 禁止事項

- `main` への直接書き込み
- force pushまたは既存履歴の改変
- セーブキー `mb_v95c` の変更
- 既存IDの改名、再利用、意味の変更
- 既存セーブ項目の削除
- 秘密情報やAPIキーのリポジトリへの保存
- 未確認のテストを成功扱いすること
- 関係のない変更を同じPhaseへ混ぜること

## 継続実行規則

- 各実行の最初に `main`、`AGENTS.md`、オープンPR、作業ブランチ、CI、進捗JSONを読む。
- 一度に扱うのは最大1 Phaseとする。
- 大きなPhaseは、同じPhase内の小さなチェックポイントへ分割する。
- 長い処理の前と、有意な作業単位の完了時にGitHubへ状態を残す。
- 実行が中断した場合は、進捗JSONの `next_action` と作業ブランチから再開する。
- 承認待ちでは、そのPhaseに依存する次Phaseを開始しない。依存せず最新 `main` から独立できる最小番号の後続Phaseだけ先行してよい。
- 承認待ちPRを親にした積み重ねブランチを作らない。
- 状態が変わっていない承認待ちでは、保留PRへ不要な追加変更を作らない。
- ローカルの一時ファイルや会話履歴だけを正本にしない。

## 診断レポートの情報区分

### 収集してよい情報

- 発生日時、アプリの版、公開コミット
- URLのoriginとpathname
- ブラウザ種別、OS種別、画面寸法、オンライン状態
- 現在画面、チュートリアル段階、待機中操作
- 錬成と遠征の診断に必要な状態
- 個数、真偽値、ID存在確認などの要約
- 最新20件以内のJavaScriptエラー要約

### 収集しない情報

- セーブデータ全文
- 個体UIDの原文
- 自由入力された個人情報
- Cookie、認証トークン、APIキー
- URLのqueryとfragment
- 不要なユーザーエージェント全文
- エラーに混入した巨大オブジェクト

診断レポートは版付きJSONと人間向け要約を持ち、各項目の取得失敗で全体が失敗しない構造とする。

### セーブ要約の契約

- 診断基盤は、セーブ機構が登録する読み取り専用プロバイダーから現在のメモリ上の状態だけを参照する。
- 出力は固定された版付きフィールドに限定し、件数、真偽値、スキーマ版、整合性異常の件数だけを返す。
- 個体UID、プレイヤー名、自由入力、モンスター・アイテム・マップ・スキルのID原文、整合性ハッシュ、ログ、セーブ全文は出力しない。
- セーブキー、スキーマ、移行処理、既存ID、保存内容は変更しない。

### チュートリアル診断の契約

- 保存されたチュートリアル状態と、画面上で進行中のステップを読み取り専用で照合する。
- 現在の状態、フローとステップ、待機中の操作種別、対象画面、対象要素の有無を固定フィールドで返す。
- 進行中なのにステップがない、対象画面が異なる、必要な操作対象が見つからない、完了状態なのに通常進行中などの矛盾を固定コードで示す。
- プレイヤー名、台詞、自由入力、セーブ全文、個体UIDは出力せず、チュートリアルの保存形式も変更しない。

### 錬成診断の契約

- 錬成を、未開始、選択中、最終確認、処理中、完了、ロールバックの固定段階で区別する。
- 素材枠数と投入総数、触媒・コイン選択の成否、候補数、検証エラー数、実行可否、次に必要な操作だけを返す。
- 処理中フラグと段階の不一致、エラーがあるのに実行可能、候補なしで実行可能、完了結果の欠落などを固定コードで示す。
- レシピ・素材・完成個体のID、触媒UID、エラー本文は出力せず、錬成結果や確率計算、消費、セーブ形式は変更しない。

### 遠征診断の契約

- 解放済み・使用中・空き遠征枠、完了回数、進行中・報酬受取可能な遠征数を固定形式で返す。
- 各遠征は進捗、必要勝利数、派遣数、報酬準備状態、序章遠征かどうかだけを最大3件返す。
- 遠征先・距離・派遣メンバーの選択状態と、派遣不能理由を固定コードで示す。
- マップID、遠征ID、個体UID、モンスター名、報酬内容は出力せず、遠征処理やセーブ形式も変更しない。

### 診断レポート生成の契約

- 環境、セーブ要約、チュートリアル、錬成、遠征、JavaScriptエラーを版付きJSONへ統合する。
- 各診断セクションを独立して取得し、一部が失敗しても他のセクションと全体レポートを生成する。
- 人間向け要約は状態、アプリ版、現在画面、検出件数、未取得セクションだけを短く表示する。
- レポート生成は読み取り専用とし、セーブ、UI、外部通信、クリップボード、ファイル保存には接続しない。

### 診断画面の契約

- 「メニュー」から診断画面を開き、最新状態への更新と元画面への復帰をスマートフォン幅でも行える。
- 人間向け要約と、環境、セーブ、チュートリアル、錬成、遠征、JavaScriptエラーの固定項目だけを表示する。
- 診断値はDOMへテキストとして挿入し、HTMLとして解釈しない。長い値は折り返し、エラー一覧は画面内でスクロールできる。
- セーブ全文、個体UID、既存ID原文、自由入力、Cookie、認証情報は表示しない。
- 診断内容は端末内で生成し、このPhaseでは保存、クリップボード、ファイル、共有、外部通信へ接続しない。これらはPhase 9で別途扱う。
- プレイヤー向けUI変更のためお知らせを追加し、マージ前にAndroidまたはChromebookで横スクロール、更新、戻る操作を確認する。

### 開発司令塔の要件契約

- 公開ゲームと開発司令塔を分離し、ゲーム側には認証情報やGitHub API処理を置かない。
- 開発司令塔は、概要、PR、自動チェック、公開、診断取込、Issue下書きの6画面を持つ。
- GitHub Repository、Actions、Pagesは読み取り専用から開始し、診断レポートは手動取込から開始する。
- 初期権限は読み取り専用かつdeny-by-defaultとする。Issue書き込みはPhase 21の明示承認付き操作だけに限定する。
- 認証切れ、API制限、部分失敗、古い情報、非対応診断版、権限不足を成功扱いせず、安全な固定状態で表示する。
- 人間向け要件は `docs/dev-command-center-requirements.md`、機械可読な正本は `docs/dev-command-center-requirements.json` とする。
- Phase 11では認証、外部API接続、画面、書き込み機能を実装しない。

### コピー・保存・共有の契約

- 診断要約のコピー、版付き診断JSONの端末保存、OS共有画面の起動を提供する。
- 各操作は診断画面のボタンを押したときだけ開始し、画面表示や更新を契機に自動実行しない。
- OS共有は安全な短文要約だけを渡し、URL、セーブ全文、個体UID、既存ID原文、自由入力を追加しない。
- 共有先の選択と送信確定はユーザーに委ね、アプリ自身は外部通信、宛先選択、バックグラウンド送信を行わない。
- 未対応API、権限拒否、保存失敗、共有キャンセルを画面内で通知し、診断表示とゲーム進行を継続できる。

### 開発司令塔の別プロジェクト基盤契約

- 実装は `tools/dev-command-center/` の独立したNode.jsサブプロジェクトとし、ゲーム本体やGitHub Pagesから読み込まない。
- 既定では `127.0.0.1` だけで待ち受け、非ループバックへ変更する場合は非公開ネットワーク確認を明示しなければ起動しない。
- Phase 12で認証なしに提供するのは `GET /healthz` だけとし、固定されたサービス状態と時刻以外を返さない。
- `.env` と派生ファイルはサブプロジェクト内でGit管理対象外にし、`.env.example` には秘密値を置かない。
- GitHub API、Actions、Pages、診断取込、セーブ、外部送信、書き込み操作、公開ホスティングには接続しない。
- 専用テストは既定のループバック、非ループバック拒否、環境変数検証、ヘルス応答の固定項目、404、安全ヘッダーを確認する。

### GitHubリポジトリ情報取得の契約

- 開発司令塔のサーバー側アダプターから、固定したGitHub REST APIへGETだけを送る。
- 対象はリポジトリ概要、直近20コミット、最大100ブランチ、最大100オープンPR、最大100オープンIssueに制限する。
- Issue一覧に混在するPRを除外し、本文、コメント、レスポンス生データは保持しない。
- コミット題名、PR題名、Issue題名、ラベル、URLを長さ制限と固定形式で正規化する。
- トークンはサーバー側環境変数からだけ受け取り、アダプターの公開状態、結果、例外、ログへ含めない。
- 一部の一覧取得に失敗しても他の取得結果を保持し、失敗部分は固定reason code付きの `unavailable` とする。
- POST、PUT、PATCH、DELETE、GraphQL mutation、権限自動拡大、ゲームクライアントへの組み込みを禁止する。

### 自動チェック状態取得の契約

- GitHub Actionsの直近20 workflow runと、最新runの最大100 jobを固定REST APIからGETだけで取得する。
- workflow名、run番号と試行番号、イベント、対象ブランチとSHA、状態、結果、開始・終了時刻を固定形式で返す。
- job名、状態、結果、失敗判定、開始・終了時刻、最大100 step、GitHub上のログ確認URLを返す。
- ログ本文、レスポンス生データ、runner名、actor情報、コミット本文、認証情報は保持しない。
- job取得だけが失敗した場合はrun一覧を保持し、job部分を固定reason code付きの `unavailable` とする。
- workflow dispatch、再実行、キャンセル、ログの自動ダウンロード、権限自動拡大、ゲームクライアントへの組み込みを禁止する。

### 本番公開状態取得の契約

- GitHub Pagesのサイト情報と最新ビルドを固定REST APIからGETだけで取得する。
- 公開状態、公開URL、ビルド方式、公開元ブランチとパス、HTTPS強制、対象SHA、作成・公開時刻を固定形式で返す。
- サイト情報と最新ビルドを独立して取得し、一方が失敗しても取得済み部分を保持する。
- 公開URLのqueryとfragment、pusher情報、エラー本文、CNAME、証明書情報、レスポンス生データ、認証情報は保持しない。
- Pagesサイト設定変更、ビルド要求、デプロイ作成・取消、公開設定変更、権限自動拡大、ゲームクライアントへの組み込みを禁止する。

### 統一ステータスモデルの契約

- Phase 13〜15の読み取り結果だけを入力にし、正常、作業中、確認待ち、失敗、公開待ち、情報が古い、取得不能の7状態へ統合する。
- すべての状態は固定のcode、label_ja、reason_code、observed_at、sourceを持ち、自由文やAIによる判定を使わない。
- 優先順位は取得不能、情報が古い、失敗、作業中、公開待ち、確認待ち、正常の順とする。
- main、CI、PagesのSHAを照合し、CI未観測、公開対象不一致、部分的取得失敗、15分を超えた観測を正常扱いしない。
- PR題名、ログ、エラー本文、レスポンス生データ、認証情報は出力せず、外部通信や書き込みを行わない。

### 次の作業判定ルールの契約

- Phase 16の固定7状態だけを入力にし、priority、action_code、reason_code、source_links、blocking_statusを必ず返す。
- 小さい数値を高い優先度とし、失敗、取得不能、情報が古い、作業中、公開待ち、確認待ち、正常の順で一意に判定する。
- 入力状態が不明または契約版が違う場合は正常扱いせず、取得不能として状態入力の復旧を選ぶ。
- 判定にAI、自由文、元データのreason codeを使わず、固定許可リスト外の値を出力へ引き継がない。
- 確認リンクはHTTPSのGitHubとGitHub Pagesだけに限定し、認証情報、query、fragmentを除去する。
- 判定処理は外部通信、GitHub書き込み、workflow操作、公開操作、承認、ゲーム本体への組み込みを行わない。

## 権限拡張の原則

後続Phaseで自動化が増えても、権限は一度に拡張しない。

1. 読み取り
2. ローカルまたは隔離環境での分析
3. 下書き生成
4. 承認付き外部書き込み
5. 限定範囲の自律書き込み

安全条件を満たす `main` マージとそれに伴うGitHub Pages自動公開だけは条件付き包括承認の対象とする。破壊的変更、手動公開、公開設定変更はPhase 32完了後も自動化対象にしない。

## Phase 0の非対象

Phase 0ではゲームコード、セーブ、UI、GitHub Actions、プレイヤー向けお知らせを変更しない。実機確認も不要である。
