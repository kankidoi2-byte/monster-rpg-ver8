# 開発司令塔 要件定義

## 目的

開発司令塔は、`kankidoi2-byte/monster-rpg-ver8` のコミット、PR、GitHub Actions、GitHub Pages、ゲーム内診断レポートを一画面へ集約し、「現在どこで止まっているか」と「次に何を確認すべきか」をスマートフォンから判断できるようにする。

Phase 11では実装や認証設定を行わず、画面、データ、認証、権限、安全な失敗方法の契約を確定する。機械可読な正本は `docs/dev-command-center-requirements.json` とする。

## システム境界

### 公開ゲーム

- GitHub Pages上のゲームは、GitHubトークン、APIキー、OAuth情報を保持しない。
- 開発司令塔の認証処理やGitHub API呼び出しをゲームへ組み込まない。
- ゲームから扱う診断情報は、Phase 0〜10で定めた安全な固定形式に限定する。

### 非公開の開発司令塔

- Phase 12以降にゲーム本体とは分離した実行領域として構築する。
- GitHubへの認証、情報集約、形式検証はこの領域で行う。
- 秘密情報は環境変数または接続先の秘密管理機構にだけ置き、リポジトリ、ブラウザ、URL、ログ、診断レポートへ出さない。

## 必要画面

1. 概要：総合状態、main、PR、CI、Pages、更新時刻、次作業候補。
2. PR：番号、タイトル、head SHA、マージ可否、CI、承認待ち理由、GitHub導線。
3. 自動チェック：workflow、対象SHA、状態、時刻、失敗ジョブ、ログ導線。
4. 公開：Pages状態、公開SHA、公開時刻、mainとの差分、公開URL。
5. 診断取込：形式版、検証結果、生成時刻、アプリ版、関連コミット、安全な要約。
6. Issue下書き：題名、根拠、再現条件、影響、重複候補。「未投稿」を常に明示する。

Phase 18で実装する画面は360 CSS px幅から利用でき、キーボード操作にも対応する。

## データ契約

| データ源 | 初期方式 | 必須情報 | 実装Phase |
|---|---|---|---:|
| GitHub Repository | 読み取り専用 | main、コミット、ブランチ、PR、Issue | 13 |
| GitHub Actions | 読み取り専用 | workflow、run、状態、head SHA、時刻、ログ導線 | 14 |
| GitHub Pages | 読み取り専用 | 状態、公開SHA、公開時刻、URL | 15 |
| 診断レポート | 手動取込 | 形式版、生成時刻、アプリ版、要約、セクション | 19 |

AIの推測を状態判定の正本にしない。Phase 16の統一状態とPhase 17の次作業は、固定コードと決定的な規則で算出する。

## 認証境界

- Phase 11では認証を実装・設定しない。
- 将来の認証はサーバー側のGitHub AppまたはOAuthを前提とする。
- ブラウザのlocalStorage、sessionStorage、URL、ゲームセーブへGitHubトークンを保存しない。
- セッションCookieは `Secure`、`HttpOnly`、`SameSite=Strict`、短寿命を必須とする。
- 認証切れは「取得不能」と表示し、成功状態を維持したように見せない。

## 権限境界

初期状態はdeny-by-defaultとし、次の読み取り権限だけを候補とする。

- metadata、contents、pull requests、issues、actions、pagesの読み取り

Issue作成権限はPhase 21でのみ、重複確認とユーザーの明示承認を条件に追加する。contents、pull requests、workflows、administration、secrets、packagesの書き込みは対象外とする。

権限を増やす場合は、目的、対象操作、失敗時の影響、取消手順を記録し、明示承認を得る。

## 診断レポートの安全境界

取り込めるのは固定コード、件数、真偽値、時刻、版、画面種別、端末区分である。セーブ全文、個体UID、自由入力、Cookie、認証トークン、APIキー、URLのqueryとfragmentは拒否する。

既定の保持期間はセッション内だけとし、外部送信は行わない。永続保存が必要になった場合は、別Phaseで保存先、保持期間、削除方法を定義する。

## 失敗時の挙動

- 認証切れ：取得不能として再認証導線だけを表示する。
- API制限：最終成功時刻と再試行可能時刻を示し、書き込みを行わない。
- 部分失敗：取得済み部分を残し、未取得部分だけを取得不能にする。
- 古い情報：成功扱いせず「古い」と表示する。
- 非対応の診断版：取り込まず、対応版を示す。
- 権限不足：自動で権限を増やさず、必要権限と対象操作を示す。

## Phase 11の完了条件

- 人間向け本文書と機械可読な要件JSONが一致している。
- 必須6画面、4データ源、公開・非公開境界が定義されている。
- 初期権限が読み取り専用で、Issue書き込みが承認対象になっている。
- 認証切れ、API失敗、古い情報、非対応診断版の安全な挙動が定義されている。
- Phase 12〜22の実装を先取りしていない。
- 決定的な検証スクリプトが成功する。

## 今回の非対象

ゲームコード、UI、セーブ、既存ID、GitHub認証、秘密情報、外部サービス、Pages設定は変更しない。プレイヤーから見える変更がないため、`js/notices-data.js` は更新しない。
