## 実装

- `battle-feedback.js` は戦闘中だけの状態。永続セーブへ追加しない。最新240件、各記録4000文字上限。DOMも240件まで。通常／複数陣営を同一形式で記録。
- 既存 `log` は互換用に残し非表示。書き込み直後に履歴へ取り込み、複数陣営の無制限なHTML追加を廃止。現在の行動は独立した読み上げ対象に表示。
- 毒・麻痺・眠り・混乱の残りT、防御／水の盾の次の被弾、溜めの次の攻撃、攻撃倍率、リンクの障壁と既存能力残数を表示。成長情報から戦闘状態を分離。
- HP変化は実損失／実回復を表示。過剰ダメージは「超過」、障壁は「障壁」、リンク軽減は「軽減」で区別。連撃は2記録と短い結果表示。回復0は+0。
- 既存単体攻撃の数字と属性演出は1回のみ。補助の結果表示は最大3行動分を同一領域にまとめ、次の行動開始で更新。演出待ちは増やさない。
- 複数陣営は敵カード・画像・HPバーを差分更新。HP残像を追加し、対象選択・詳細展開時にも画像要素を保持。
- 操作中は既存busy判定に加え、操作部をinertにし処理中と明示。戦闘終了時は履歴を残し結果パネルを通常フローで表示。
- 通常の次戦で履歴初期化。チュートリアルの2連戦と乱入では履歴を維持し、新たな敵の登場を回復と誤認しない。
- 狭い画面で状態が多い場合は状態領域をスクロール可能にする。履歴／能力・成長／マップ条件は折り畳み。極端な小画面や多状態では全てを1画面へ強制圧縮せずページのスクロールを許可する。

## 検証方法

- `npm run check`（postcheck含む）。既存リンクの表示テストは参照先が共通表示へ移ったことを検証するよう更新。
- `npm run check:battle-readability`: 実戦関数のHP、回復上限、連撃、過剰ダメージ、毒、反動、状態解除、同一メッセージの履歴保持を検証。基準mainとの13種類の計算・乱数回数比較を行う。
- `scripts/battle-readability-browser.html` は明示的な検証入口。通常のindexからは読み込まない。検証用個体をメモリーに生成し、saveGameを無効にして実戦関数を動かす。
- 実ブラウザーのiframeで360×640、320×568、412×915、844×390を確認。ブラウザーの物理Android検証とは区別する。

## 実機確認と制約

- Androidで技の開閉、対象選択、戻る、文字サイズを大きくした状態、ブラウザーUIの出入りを確認する。
- OSの「アニメーションを削除／動きを減らす」で数字と状態が残ること、チュートリアルの対象強調とコマンド操作を確認する。
- 長い技名、多数の状態、三つ巴の小画面ではスクロールが必要になり得るが、固定操作部による遮蔽は生じない設計。

- 本番マージは別途の依頼とAndroid確認を待つ。

## 確認結果

- 通常戦・技選択中のHPと操作ボタンの位置を実ブラウザーで測定。320×568では味方HP 260–279px、敵HP 152–171px、操作ボタン496–544px。360×640では味方285–304px、敵151–170px、操作548–596px。412×915では味方420–439px、敵213–232px、操作687–735px。844×390では味方263–282px、敵158–177px、操作264–318px。マップ条件／長い名前／状態数によって高さは変わる。
- 三つ巴の360×640・技選択中は味方HP336–355px、操作572–620px。画像とHPバーのDOM同一性も実ブラウザーで確認。
- ブラウザー追加検証14項目が成功：回復上限、連撃2発、HP個別記録、毒と解除、吸収、反動、行動不能と解除、複数陣営のDOM保持、複数陣営の回復、障壁、連打、撃破と報酬重複、履歴件数、次戦初期化。
- CIの全ゲーム検証は初回から成功。別枠の報酬ソース一致チェックは表示呼び出しも差分として扱ったため、勝利・契約処理への表示フックを除去し、勝利ログは共通の結果画面側で記録するよう変更。検査基準を緩めず `npm run check:world-map-economy` が成功。
- 実機AndroidおよびOSの動きを減らす設定での最終確認は未実施。低モーション分岐／CSSの既存チェックと数字の静的表示は維持。
