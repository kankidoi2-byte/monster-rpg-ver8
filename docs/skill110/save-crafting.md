# セーブ移行・技合成

## 実装範囲

- 保存キー `mb_v95c` と `MonsterProfiles` のプロフィール別保存キーを維持。
- スキーマ v4 の既存互換移行後、`repairSave` の技能ID正規化より前に110体系への移行を実行する。初回読み込み・ファイルインポート・バックアップ復元はいずれも同じ `parseAndPrepareSave` / `repairSave` 経路を通る。
- `saveMeta.migrations` の `skill_system_110_v1` と `skill110Migration.version=1` を記録する。新規セーブは最初から完了マーカーを持ち、旧データ向け補填や更新通知は行わない。
- 技変更前のペイロード全体を `skill110MigrationBackup` に保存する。通常の `lastKnownGood` に加え、移行前データが新セーブとともに残る。既存スキーマ v0→v4 の正規化はこのバックアップより先に行われる。
- マップにある旧IDを各キー一度だけ変換し、同じ新IDになるカード枚数を合算する。従来のID正規化にあった `max` 集約や旧「全99枚の廃止」処理を先に通さない。これにより現在持っている枚数を保存する。
- 未知の将来IDは無条件に共通技へ変換せず、枚数付きで `skill110UnmappedCards` と全体バックアップに保存。マーカーのない旧インポートに最強IDが混じる場合も隔離し、移行経由では取得させない。既に110へ移行済みで合成した最強技はそのまま維持する。
- 旧装備を変換し、適性・3枠・個体レベルごとのCOST予算・全個体合計の所持カード枚数に収まる枠のみ保持。外したカードは所持品に残す。
- 攻撃技がなくなった個体にはCOST1「一撃」を優先的に所持品から割り当て、不足時だけ1枚補填。必要なら最後の補助枠を外す。補填数は記録し、マーカーにより再読込では繰り返さない。
- 現行の技図鑑は全技/所持情報から表示され、専用の図鑑保存配列はない。互換インポートに `skillDex` / `discoveredSkills` / `knownSkills` がある場合は既知IDを移行して履歴を保持する。
- 旧進化固有カード補填・旧装備カード再構築は110移行後には実行しない。新規獲得・進化カード配布も合成限定カードを除く。

## 合成トランザクション

4レシピは `js/skill-synthesis.js` の `SKILL110_SYNTHESIS_RECIPES` を唯一の定義とする。素材順は問わず、各1枚を消費して完成技1枚。追加通貨・失敗抽選なし。

1. `previewSkillSynthesis` は素材枚数、装備から外れる個体・技・枠、および状態に結び付いたトークンを返す。
2. 全個体の装備数が消費後の所持枚数を超える場合に限り、超過する枠を明示して確認が必要。未使用カードが足りるなら装備は維持。
3. `executeSkillSynthesis` は素材、状態一致、確認有無、排他フラグを再検証。
4. 同じセーブオブジェクト内で素材減少・装備解除・完成技増加・取引番号を変更し、既存 `saveGame` により一回の主保存キー書き込みへまとめる。
5. 保存失敗/例外ではセーブのメモリ状態を全体復元。成功時にプレビュートークンを無効にする。二重要求・古い状態の要求は拒否。
6. 再起動時は完了済みセーブを読むだけで、合成要求を再実行しない。既存プロフィールの保存競合検知も維持。

装備から技を消費した後の空き枠はそのまま残し、プレイヤーが選び直せる。合成時に無償の攻撃技を繰り返し配らない。

### インポート・復元の保存失敗

実際のファイルインポートおよび `restoreLastKnownGood` は、主保存に失敗した際に元のライブセーブ・修復記録・直前バックアップを復元し、再読込しない。これにより「失敗」と表示した後に未保存のインポート内容がそのまま残り、次の通常保存で元データを上書きする経路を防ぐ。上記単体テストは実際の非同期 `importSaveData` を呼び、取消・主保存の容量エラー・成功・成功後読込を検証する。
