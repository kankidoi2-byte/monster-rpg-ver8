# アップデート報酬の運用・確認

- `js/update-releases.js` の末尾に、内部管理用の連番 `version`（例: 8.0.7、8.0.8）、日本時間の日付 `date`、変更点1行 `change` を1件追加します。最初の8.0.1は移行の基準行なので、削除・変更しません。公開済みの行も同様です。
- `index.html` の `js/update-releases.js?v=` をその番号に更新します（再訪時の古いキャッシュを防ぐため）。報酬の見出しには月日を表示します。お知らせは `js/notices-data.js` に登録します。同じ日付の既存記事を確認し、修正は「不具合修正」、機能・音の追加は「アップデート」として、変更内容が分かる見出しで各1件にします。
- 上乗せする更新だけ `extraRewards: [{kind:'item',id:'revive_drop',count:1}]` のように書きます。通常分を置き換えません。報酬の種類・IDは既存のプレゼントと同じです。
- 自動報酬は番号の上げ方にかかわらず、毎回コイン100枚とG-BLESS 10です。G-BLESSは週間分ではなく予備の加護へ加算します。受け取り操作・解放条件は既存のBOXと同じです。

## 隔離セーブでの動作確認

Playwright の Chromium を用意し、`npm run check:update-rewards` を実行します。開発サーバーだけを使い、更新一覧・個別ギフトの通信はテスト内で差し替えます。

| ケース | 操作と期待結果 |
|---|---|
| 新規 | 8.1.0で空のブラウザを起動すると過去分は0件。9.0に切り替えて再起動すると9.0のみ届く。開設記念セットは元の条件で表示。 |
| 既存 | 報酬欄のない旧セーブを8.0.1で開くと、所持品・残高はそのまま。8.0.1までの報酬は届かない。 |
| 数件スキップ | 8.0.1から9.0へ。小の報酬が3件届き、設定した更新だけ追加報酬が上乗せされます。変更点は告知と一致。まとめて受け取ったあとの再読み込みで再配布されない。 |
| 20件超 | 同じ日付で24回更新すると新しい20件だけ残る。1件受け取って再読み込みしても消えた古い4件は戻らず、開発者・意見箱の品は減らない。 |
| 保存できない | 受け取り処理中に保存を失敗させると、報酬残高とBOXが受け取る前の状態に戻る。 |
