## 修正前の再現

実草原requestで110技の鉄壁の構え/不退の構え/オーバーリバースを使用しても、旧ID敵技の経路では防御を真偽値として45%へ固定していた。

第11話・雷嵐（威力48、採用攻撃補正0.75、乱数0）：無防御36。防御40/45/60/70%で全て19ダメージ。正しくは21/19/14/10。
第3話・若葉の突進（威力24、補正0.85）：無防御20、防御40/45/60/70%で全て11。正しくは12/11/8/6。

## 変更

- 単体/複数の旧技攻撃から共通の数値防御処理を呼ぶ。
- 技防御/水の盾/リンク軽減は強い値だけ使用。有限HP障壁はその後に消費。
- 追加攻撃も同じ防御・回避結果を利用し、回数制能力を二重に消費しない。HP障壁の残量は各ヒットに従って減る。
- 110技の既存全ダメージ処理は一度だけ同じresolverを呼ぶ動作を維持。
- 毒/反動へ防御を適用しない。既存旧吸収の計算は今回変更しない。
- 全技/敵/原稿/進行/経験値/取得/合成のデータ値、保存形式は変更しない。

## 検証

`node scripts/test-story-legacy-defense.mjs`：41ケース。草原第1/3/11話の実敵、各防御値/盾、リンク/回避/追加攻撃、味方→敵/敵→敵、弱い110防御で強い防御を置き換えない、毒/反動。

既存の防御以外の歴史的効果/RNG比較は継続。歴史的エンジンとの完全一致試験は意図的に変更した「二重軽減/最初のヒットのみ防御」の初期状態を使わず、新しい独立した数値期待値行列で置き換えて検証する。旧resolverだけを模擬していた障壁fixtureは、新resolverにも同じ模擬障壁を接続。実際の有限障壁と回数消費は新行列で検査する。

`npm run check`（postcheckを含む）は修正後に全PASS。草原2,200戦の集計も修正前と全項目一致した。Node VMでは描画/保存/アニメーションをstubするため、Android実機操作とは区別する。

既存旧技のguard効果自体（booleanの付与）や集中/吸収の再設計は含めない。現行プレイヤーの110補助技は強い防御を保持する。原稿の全敵技に追加攻撃技はないが、互換戦闘の回帰を防ぐため追加攻撃も検証する。

本PRはレビュー用。main統合・本編公開は行わない。
