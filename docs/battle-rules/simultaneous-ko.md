# 同時KO時の勝敗判定（2026-10-06）

## 仕様と範囲

開発元main `7e952ab2d905f99a963a61122642465de3e71d6a` で未修正を確認。単体戦の既存仕様とユーザー承認に合わせ、複数戦も全敵の戦闘不能を味方の戦闘不能より先に判定する。

- 味方と全敵が同時に倒れた場合は勝利。控えの有無にかかわらず交代しない。
- 敵が残る場合は従来どおり生存する控えに交代し、控えがいなければ敗北。
- `runMultiActions` の攻撃完了後と `finishMultiBattleTurn` の全状態効果解決後で、既存 `winMultiBattle` を先に呼ぶ。
- 攻撃計算、反動、毒、COST、ネメシオンの攻略法、撃破/毒の帰属、契約条件、報酬・経験値・進行関数、保存形式・IDは変更しない。HP負数の別課題は対象外。
- 既存 `battleRewardGranted` と各敵の `rewardGranted` を維持し、勝利/報酬を新規実装しない。

## 差分

実行コードの変更は判定順の2か所のみ。告知と2つのスクリプトのキャッシュ識別子を追加する。新しいVM回帰を既存 `check:battle-readability` に、実ブラウザー回帰を現行validateジョブに接続する。

直前の反動説明回帰は複数戦ソース全体を固定していたため、今回の承認済み判定順変更も拒否した。固定対象を `performMultiAttack` 全体へ絞り、反動計算・乱数・効果の不変検査は維持する。単体戦ルール全体と技データ・説明の既存不変検査も維持する。

## 回帰と証拠

- `scripts/test-simultaneous-ko.mjs`: 3戦闘形式（単体・三つ巴・実乱入移行）×3原因（味方反動・敵反動・毒）×控え有無×敵生存有無の36条件、通常勝利/敗北/継続18条件、実際の敵同士攻撃/毒の帰属8条件、合計62条件。
- 実際の攻撃・判定・交代・勝利・経験値・コイン・進行関数を利用。表示とモーションはVMハーネスの代替処理。乱数と単体戦の技/行動速度だけをfixture内で固定し、終了後に復元。
- 同時KO勝利で交代0回。反動自滅や敵由来毒をプレイヤー撃破へ変えない。報酬/進行の呼出し数、勝利回数、敵別報酬フラグ、重複勝利呼出しの無作用を確認。
- 実 `saveGame` と `parseAndPrepareSave` でコイン、勝利履歴、パーティー、個体、所持品、カード、装備、進行の一致を確認。戦闘中の一時状態を保存・復元する機能は追加しない。
- 修正前mainで回帰を実行すると、三つ巴・味方反動・控えなし・全敵KOで敗北となり失敗する。修正後62条件は成功。
- `scripts/test-simultaneous-ko-browser.mjs`: 同じ62条件を実index/DOM/戦闘/保存関数で検証。タイトル→ホーム→編成→討伐選択→戦闘、実契約候補表示、単体/三つ巴/乱入の保存後のページリロードと再戦、ページ例外0件を検査。390×844、reduced-motion。3形式の同時KO画面とJSONをCI artifactへ保存。
- 全体検査は `npm run check`（postcheck含む）、現行PR headでvalidate CI（全体検査、報酬比較、既存の画面テストと今回の画面回帰）の成功を統合条件とする。

ローカルのブラウザー導入はダウンロード内容の破損で失敗したため、実画面検証はGitHub Actionsで実行する。未観測のCIや画面検証を成功扱いにしない。Android/Galaxy/Chromebook実機、全難易度・全キャラの通しプレイは未実施。
