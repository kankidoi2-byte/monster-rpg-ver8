## 5. Rollback判定

次のいずれかが再現したら新規プレイを止め、公開後点検を不合格とし、rollbackを検討する。

- `mb_v95c`が初期化される、既存UID/所持品/party/lock/物語進捗が失われる
- 序章が再開不能、報酬が重複、世界地図から戦闘へ進めない
- 黄金郷の地図が閲覧だけで消える、イベント入口が敗北/再読込だけで失われる
- Android/Chromebookで主要CTAが押せない、恒常的な白画面や操作不能になる

軽微な文言・装飾だけの問題は、セーブ互換性を壊さない修正PRを優先する。データ破損や進行不能では公開継続より復旧を優先する。

## 6. Rollback手順

1. 問題端末で追加操作を止め、更新後JSON、Console/通信エラー、対象SHA、再現手順を保存する。
2. GitHub上で公開に使ったmerge commitを通常のrevert commitで戻す。force pushや履歴改変はしない。
3. 公開版には地図案内9ステップの`persistAs`互換ガードが含まれるため、公開後に作られた途中セーブは旧mainの`elna_guest_join`、`stella_intro`、`lumina_intro`へ解決できる。短い会話/経路が再案内される場合はあるが、報酬や副作用のあるstepをrollback先にしない。
4. revertのCI成功後、新規、序章途中3地点、完了、スキップ、既存セーブで読込と再開を確認する。
5. 端末データだけが壊れた場合は、まずメニュー → `直前のバックアップへ戻す`を使う。復旧しなければ公開前JSONを`セーブを読み込む`から取り込み、個体数・コインを確認して承認する。`セーブデータをリセット`は復旧に使わない。
6. rollback後も読めないJSONは上書きせず保全し、`修復・移行記録`とともに5Cへ戻す。
