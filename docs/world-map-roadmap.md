# モンスターバトル本編：世界地図システム完成ロードマップ

版：1.1／状態：自動開発用に26作業へ分割。実装状況は開発ブランチの進捗正本を参照。

## 目的と完成の定義

「バトル → 世界地図 → 場所選択 → 探索・試練 → 戦闘 → 契約・報酬 → 再探索／地図」を一つのゲーム体験として完成させる。地図、世界の出来事、正式な演出を整えた後、チュートリアルを新しい操作へ改修する。新規開始、既存セーブ、途中再開のいずれでも遊べ、公開版で動作確認できた時点を完成とする。地図の表示だけ、段階3の見た目完成だけでは完了にしない。

当初はロードマップ作成の依頼だったが、その後、段階0〜5を可能な限り自動で進める指示を受領。公開承認の取得と公開後確認を含む完成条件は維持する。第8節の分割・実行ルールを優先する。

## 1. 採用する方針と未確定事項

### 採用方針

- 現行19マップの名前・ID・出現種を基礎に、王都と中央平原を中心とする広域地図を作る。
- 光の女神エリシアは光の平原へ確率で「降臨」する。通常の野外出現から降臨時の試練へ遭遇経路を移し、星4を維持する。
- 序章の世界の危機は星5「滅亡の星 ネメシオン」。偽竜は世界の危機に反応して介入する存在とする。
- 偽竜との遭遇のために、プレイヤーへ危機の放置を強制しない。
- 世界の狭間は地理・時間の外側にある領域。将来の別世界・過去・未来への接続余地を残す。
- 最初の3段階の後にチュートリアル改修を置き、統合検証と公開確認まで行う。
- 地形画像と、地名・選択地点・出来事の表示を分離する。既存の個別マップ画像を詳細画面で再利用する。
- セーブキー mb_v95c、既存ID、所持品、契約体、ロック、図鑑、物語の進捗を維持する。

### 開発開始時に仕様化する暫定案

- 降臨・危機・秘境の抽選頻度、救済条件、共存数。以前の「5％・30勝救済」は危機の試作値であり決定値ではない。
- 危機は発見後に保持し、挑戦・再挑戦・明示的な見送りを選べる案。現実時間による強制消失は初期実装では採用しない。
- 危機を討伐しても見送っても、偽竜の痕跡から遭遇機会を得られる案。見送り時の介入は報告で表現し、自動戦闘は作らない。
- 地理上の道は場所の関係を表す。移動待ち時間や全マップの順番攻略は必須にしない。新規の解放制限を設ける場合、既存プレイヤーの訪問権を損なわない。
- 「偽竜は人間の被害を顧みない」は追加の世界観提案に留め、今回の必須設定にはしない。
- 王都をホームの拠点とする案、降臨時の加護の具体効果は、既存シナリオとの整合を確認して確定する。

## 3. 工程と完了条件

全工程は未着手。依存順は 0 → 1 → 2 → 3 → 4 → 5。工数の確約より、各工程の通過条件で進行を判断する。

### 段階0：仕様と互換性の確定

作業：

- 実装開始時点の最新mainと既存の進捗正本を確認し、この計画との差分を記録する。
- マップ・難易度・敵候補・特殊マップ・乱入・三つ巴・報酬・遠征・図鑑の参照関係を棚卸しする。
- 19マップの地点情報、入口、通常探索と特殊遭遇の区分を確定する。
- 世界の出来事の状態遷移と保存方式を決める。章、世界、時代、地域、既存mapIdを混同しないデータ構造にする。
- 新規・途中・完了済みチュートリアルの移行方針をこの段階で設計する。実際の案内改修は段階4で行う。
- 難易度は原則Easy＝星1・Lv1、Normal＝星1〜3、Hard＝星2〜4、Extreme＝星5・Lv100を継承。候補のいない難易度は選択不可にする。
- スライム・ゴールド・素材の狙い撃ちによる入手速度を基準化し、地図化後の比較方法を決める。

成果物：仕様書、接続表、状態遷移表、移行表、受入確認表。

完了条件：遭遇不能になる既存対象や入手不能になるアイテムがないことを仕様上確認。仕様の空白を残したまま本番の抽選処理を書き始めない。

### 段階1：地図から一連の冒険ができる基盤

作業：

- 仮地図と地点選択を実装。王都の施設はまとめて表示し、深海・星界などへの遷移を用意する。
- 場所の詳細に既存画像、出現候補、対応難易度、図鑑への導線を表示する。
- 出発時に敵を抽選し既存の戦闘へ接続。戦闘後の契約・報酬から再探索／地図へ戻れるようにする。
- 模擬戦・演習・手合わせの名称を場所に合わせる。戦闘と契約の扱いは既存ルールとの整合を確認する。
- 黄金郷と流水の秘境などを、仮の特殊入口として利用可能にする。黄金郷への地図は入場時だけ消費する。
- 遠征、図鑑登録、乱入、三つ巴、討伐報酬との接続を維持する。

成果物：19マップへの経路を持つ動作版、既存バトルへつながる探索画面。

完了条件：対応する全マップ・難易度で敵候補が成立し、探索→戦闘→契約／報酬→再探索→保存／再読込が通る。途中段階で旧チュートリアルを壊した状態を一般公開しない。

### 段階2：降臨・危機・偽竜と特殊領域

作業：

- 出来事の発生、保持、挑戦、敗北、再挑戦、解決、見送り、記録の状態を実装する。
- 判定を探索結果等の確定した進行に連動させ、同じ結果から抽選・報酬が二重に発生しないようにする。
- 光の平原の通常候補から女神エリシアを外し、降臨から星4の試練・契約へつなぐ。他の出現経路や乱入でも降臨制限を抜けないか確認する。
- 星空の平原から滅亡の星ネメシオンの危機へ進めるようにする。危機がない場合の星4ネメシオンの経路も維持する。
- 危機解決・見送りの双方から偽竜の痕跡を扱い、alfa・beta・gammaの遭遇機会を公平に設計する。偽竜を倒したことで危機が無限連鎖しないよう原因イベントを区別する。
- 通常探索を続けられるようにし、世界の狭間を将来の接続先追加に対応させる。
- 黄金郷や秘境と降臨・危機が重なっても、当選した入口を上書きで消さない。共存ルールを仕様化する。
- 光の平原の旧説明「ヒカリの群れ」などを現在のキャラクター設定に合わせる。

成果物：状態保存に対応した全出来事、発生と解決の地図表示、記録。

完了条件：発生直後・敗北後・見送り後・解決後の保存／再読込で矛盾がない。ネメシオンを倒した人が偽竜の機会を失わず、錬成限定エリクシオンが野外に混入しない。未調整の抽選値は暫定値として明記する。

### 段階3：正式な地図画像と演出・スマホ操作

作業：

- 確定した配置を基に正式な地形画像を制作。地名、ボタン、イベント目印はゲーム側で重ねる。
- 小画面で地点が密集する場所を拡大表示や施設まとめで解決する。地図から戻った際の表示位置を保持する。
- エリシア降臨の光、滅亡の星の予兆、偽竜の裂け目、解決後の景色を実装する。
- 色だけに頼らず名称と記号でも状態を伝える。動きを抑える設定では演出を軽減する。
- 画像読込中・読込失敗時にも地点を操作できる代替表示を用意する。
- 画像サイズと描画負荷を調整し、既存の画像予算・検証ルールを守る。

成果物：正式な地図、出来事の演出、モバイル向け操作。

完了条件：320〜430px程度の画面幅で地名・ボタン・詳細が重ならず、下部ナビに隠れない。画像未読込でも進行できる。これは見た目の完成であり、プロジェクト全体の完了ではない。

### 段階4：チュートリアルを世界地図方式へ改修

作業：

- 既存の序章の物語と話ごとの区切りを維持し、地図を使う実操作へ案内を置き換える。
- 最初の探索では、バトル入口→草原選択→詳細確認→探索→戦闘／契約→地図に戻る、を実際に経験させる。救援戦との重複を整理し、説明のためだけに戦闘を増やさない。
- 王都の施設への移動を、ステラの技説明とルミナの錬成への流れに合わせる。
- 遠征の草原選択、黄金郷の案内、報酬受領、自由行動への移行を新しい導線に合わせる。
- 降臨・危機・裂け目は初めて発生した時の短い補助説明で案内する。序章完了にランダムイベント発生や星5討伐を要求しない。
- 初回の必要な探索は確定で進められるようにし、抽選待ちや高難度イベントによる割り込みを防ぐ。
- 新規開始、旧版の途中再開、完了済み、スキップ済みを別々に処理する。完了済みプレイヤーには短い地図紹介だけを出し、報酬・加入を再付与しない。
- 画面を閉じる・再読込・セーブ読込でも、案内対象と進行状態がずれないようにする。廃止した再閲覧方式を再導入しない。

成果物：新地図に対応した序章、新旧進行の対応表、初回出来事の補助説明。

完了条件：新規セーブから序章を完了し、説明なしで自由探索に進める。途中で止めても再開でき、完了済みセーブでは序章をやり直さない。全ての必須案内で実際に押せる対象が存在する。

- 探索の自由化による経験値・ゴールド・素材・契約体入手速度を比較し、必要な調整のみ行う。
- Android実機で地図操作、契約、画面復帰、再読込を確認する。Chromebook相当の表示・操作も検証し、実機未確認なら区別して報告する。
- プレイヤー向け更新告知、セーブの事前書き出し案内、公開対象の差分と検証結果を整える。
- リポジトリの承認ルールに従って公開する。旧版へ戻す場合も、新しいセーブを壊さない復旧方法を先に確認する。
- 公開URLで画像・操作・セーブ継続を確認し、公開後に見つかった必須不具合を修正する。

成果物：検証報告、公開済み本編、公開後の点検記録。

## 5. 作業の分け方と進捗管理

作業単位の推奨順：仕様／地理データ → 地図UI／探索接続 → 特殊入口互換 → 出来事基盤 → 降臨 → 危機／偽竜 → 地図素材／演出 → チュートリアル／移行 → 統合調整／公開。

各単位で変更内容、確認結果、残課題、次の作業を記録する。複数エージェントを使う場合は、地理・文章、地図UI、状態管理、検証を明確に分担し、同じセーブや戦闘ファイルへの同時編集を避ける。統合責任者を一人にする。並列化は工程の依存関係を省略する理由にしない。

チュートリアルの依存調査は段階0から行うが、本格的な改修は段階3後に行う。段階1〜3の動作版は開発用として確認し、一般プレイヤー向けの完成公開は段階4・5を通過してから行う。既存本編で進行中の別改修は開始時に確認し、無関係な変更を混ぜない。

### 実行と引継ぎのルール

- 毎回、前提を満たした未完了項目から最も完成に寄与するものを選ぶ。1項目が終わったら時間・能力の範囲で次へ進む。定刻まで待つ必要はない。
- 各項目は「未着手・作業中・実装済/検証待ち・検証済・外部待ち」に分ける。全26項目の単純な割合を工数進捗率と呼ばない。
- 進捗正本にはID、担当実行、前提、対象ファイル、変更した仕様、コミットSHA、検証コマンドと結果、未確認事項、停止理由、次に行う具体操作を記録する。作業中断前には可能な限り開発ブランチへ保存する。
- 担当取得は利用可能な実行状態とGitの競合検出で確認する。信頼できる実行状態を取得できない場合、古い時刻だけで担当を奪わない。その制約を0Aで明示し、再開不能の原因を隠さない。
- 技術的不具合は再現→原因→修正→必要な再確認まで進める。同じ失敗を根拠なく繰り返さない。行き詰まった項目は試したことを保存し、依存しない実装・検証・文書作業があれば続ける。
- 認証・権限・利用上限・自動承認レビュー拒否を迂回しない。実機確認をブラウザ模擬表示で代替したことにしない。外部待ちのため他に進められる作業がなくなった時だけ、再開条件を報告して定期タスクを一時停止する。
- 画像生成や確認手段が利用不能でも、仮素材で可能な機能改修を進める。正式素材・視覚確認の未完了を隠して完成扱いにしない。
- 必要に応じて独立した素材・データ監査・レビューをサブエージェントへ分担できる。同じ共有ファイルの同時編集は避け、統合担当が取り込みと検証を行う。
- 自動レビューは品質点検として利用できるが、ユーザー本人の公開承認を代理して出せない。現時点の依頼は承認依頼までの自動進行であり、無条件の本番公開許可とは解釈しない。承認待ちにする前に、利用可能な手段で準備できる成果と検証を仕上げる。
- 後からユーザーが公開を明示承認した場合、その範囲と対象を確認して5F・5Gを進める。既に一時停止したタスクが発言だけで再有効化されるとは仮定せず、必要なら再開設定を更新する。

今回の改訂で完了したのは作業分割と定期タスク指示の更新。ゲームコードの実装完了を意味しない。
